## Claims

1. **Chrome helpers live in `chrome/overlay-box.ts` and are the canonical panel-drawing primitives.** Exports: `topBorder`, `divider`, `bottomBorder`, `row`, `topBorderSplit`, `dividerSplit`, `splitRow`, `splitBodyWidth`, `PanelRows`, `PanelDivider`, `OverlayPanel`. All paint with `theme.boxRound` + `border`/`accent` colors. `overlay-box.ts:1-12` docstring: "Everything paints with `theme.boxRound` glyphs (rounded corners, sharp tee/cross junctions) and the `border`/`accent` theme colors so all outlined overlays read identically." [primary, 2026-10-26]

2. **`theme.boxRound` is a getter on `Theme`, returning an object with `topLeft/topRight/bottomLeft/bottomRight/horizontal/vertical` (rounded) + `cross/teeDown/teeUp/teeRight/teeLeft` sourced from `boxSharp.*` tokens.** `theme-class.ts:553-570`. There is also `boxSharp` (583+) and `boxDotted` (574+). A plugin reading `theme.boxRound` must guard for undefined (host half-built theme) — plugin already does in `panel.ts:boxVerticalOf`. [primary]

3. **Theme singleton is `export var theme: Theme` (mutable).** `theme/theme.ts:104`. Undefined until `initTheme()`/`initThemeSync()` assigns. Host hands plugins an injected theme via `ctx.ui.custom` factory; plugin's panel.ts documents this ("pi-tui `theme` module export is `export var theme: Theme` — undefined until initTheme() runs"). [primary]

4. **Theme init helpers:** `initThemeSync(symbolPreset?, colorBlindMode?, darkTheme?, lightTheme?)`, `ensureThemeSync()` (calls initThemeSync if undefined), `setThemeInstance(themeInstance)`, `onThemeChange(callback)` returns unsubscribe, `getThemeEpoch()`. `theme/theme.ts:187,205,339,428`. Plugins should call `ensureThemeSync()` early and prefer the injected instance; `onThemeChange` to repaint. [primary]

5. **`bindTheme(binding)` mirrors assignments into bundled module bindings** — plugins can bind to keep a local `theme` var live. `theme/theme.ts:116`. [primary]

6. **Theme class methods:** `fg(color, text)`, `bg(color, text)`, `bold(text)`, `symbol(key)`, `styledSymbol(key, color)`, `getSymbolPreset()`, plus category getters `status`, `nav`, `tree`, `progress`, `boxRound`, `boxSharp`, `boxDotted`, `checkbox`. `theme-class.ts:350-397, 470-496, 553+`. [primary]

7. **Layout primitives:** `components/layout/geometry.ts`, `row.ts`, `split-pane.ts`, `stack.ts`; `components/box.ts`, `spacer.ts`, `text.ts`, `markdown.ts`, `select-list.ts`, `scroll-view.ts`, `tab-bar.ts`, `table.ts`, `tree-view.ts`. Plugin uses `SplitPane`, `Stack`, `visibleWidth` from `@oh-my-pi/pi-tui`. [primary]

8. **Message framing helpers:** `chrome/message-frame.ts` exports `FramedMessage`, `FramedMessageComponent`, `FramedRenderer`, `FramedMessageOptions` — the canonical chat-block frame. `chrome/chat-block.ts`, `message-divider.ts` (labelled rule with cache + native describe), `message-notice.ts`, `error-block.ts`, `status-notice.ts`. Plugins should reuse `FramedMessageComponent` instead of hand-rolling frames. [primary]

9. **Render layer:** `render/tool-card.ts`, `render/output-block.ts`, `render/composite.ts`, `render/hanging-wrap.ts`, `render/tree-list.ts`, `render/status-line.ts`, `render/file-list.ts`. Tool cards use `render/tool-card.ts` + `tools/default-renderer.ts`. [primary]

10. **Overlays:** `overlays/extensions/inspector-panel.ts`, `live-tool-session.ts`, `mcp-runtime.ts`, `state-manager.ts`, `types.ts` — extension overlay contract. `overlays/hub-frame.ts`, `bordered-loader.ts`, `pause-screen.ts`. [primary]

11. **Status line:** `status-line/component.ts`, `footer.ts`, `host.ts`, `segments.ts`, `separators.ts`, `metrics.ts`, `context-usage.ts`, `presets.ts`, `loop.ts`, `startup.ts`. `chrome/transcript-status.ts`, `chrome/transcript-container.ts`. [primary]

12. **Native describe/tone:** host uses `native/describe` (`node`, `card`, `col`, `span`, `text`, `md`), `native/tone` (`colorTone`), `native/memo` (`Memo`), `native/node` (`NativeNode`, `DescribeContext`). Plugins doing custom UI can adopt these for native surfaces. [primary]

13. **Plugin's hand-rolled framing:** `plugin/src/panel/chrome.ts` wraps host `topBorder/topBorderSplit/divider/dividerSplit/row/bottomBorder` with `fitWidth`/`fitBlock` because "overlay-box helpers under-fill/over-fill". This is a symptom of not using `OverlayPanel`/`PanelRows` which already handle height budgets. [primary — plugin source]

14. **`OverlayPanel` (overlay-box.ts) is the container for inline overlays hosted in the editor slot or anchored container** with memoized rows, height pinning, native describe. Plugins should prefer it over manual row assembly. [primary]

15. **Plugin's theme shim (`host-theme.ts`)** snapshots symbols and captures `boxRound` fallback (`BOX_ROUND.vertical`) because host theme may be half-built. This matches host reality (theme singleton may be undefined early) but the fallback glyph should come from host's `boxRound` once available, not a constant. [primary — plugin source + host]

## What the "right" way is
- Use injected `ctx.ui.custom` theme; never read module singleton at render.
- Call `ensureThemeSync()` at extension load.
- Use `theme.boxRound`/`boxSharp` getters (not cached constants) so theme switches propagate; use `onThemeChange` to invalidate caches (MessageDivider does via `getThemeEpoch()`).
- Frame panels with host chrome: `OverlayPanel` + `PanelRows` for height budgeting, `topBorder`/`divider`/`bottomBorder`/`row` for string rows; `FramedMessageComponent` for chat blocks; `MessageDividerComponent` for dividers; `MessageNoticeComponent` for notices.
- Use `Memo` + `getThemeEpoch()` for native describe caching, as host does.
- Color via `theme.fg`/`theme.bg`/`theme.bold`; symbols via `theme.symbol()`/`theme.status`/etc., not hardcoded glyphs.
- Layout via `SplitPane`/`Stack`/`Box`/`Spacer` rather than manual padding where possible.

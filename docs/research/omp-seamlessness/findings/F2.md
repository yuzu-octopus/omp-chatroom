## Plugin host-theme.ts gap analysis

- `hostRealTheme(init)` calls `init(preset, colorBlind, keep, keep)` where preset/colorBlind come from `getSymbolPresetOverride()`/`getColorBlindMode()` and name from `getCurrentThemeName()` (unless "<in-memory>"/empty/undefined). This is the correct way to build a theme with user settings WITHOUT wiping them (unlike `ensureThemeSync()` which calls `initThemeSync()` with undefined args). `plugin/src/panel/host-theme.ts:104-149`. [primary]
- `adoptHostTheme(theme)` publishes into host singleton via `setThemeInstance` ONLY when host theme is not already usable; otherwise no-op. This keeps plugin from clobbering host's real theme. `host-theme.ts:152-194`. [primary]
- `uncolouredTheme()` builds a last-ditch object satisfying EVERY Theme member with neutral grey/ascii box chars. `host-theme.ts:670-902`. [primary]
- BOX_ROUND exported is `liveTable(BOX_ROUND_KEYS)` resolving through host's active symbol lookup at access time, with junctions borrowed from boxSharp. `host-theme.ts:597`. [primary]
- The plugin's own `theme` param in RoomPanelOptions is the injected host theme; never read module singleton. `panel.ts:44-58`. [primary]

## What is correct way to publish fallback theme

1. Prefer the injected `theme` from `ctx.ui.custom` factory (host's live theme).
2. If unavailable, `hostRealTheme()` builds one with user settings via `initThemeSync(preset, colorBlind, name, name)` — preserves preset/colorblind/theme name.
3. Only as last resort, `setThemeInstance(uncolouredTheme())` — but only when host has nothing usable (`adoptHostTheme` guards).
4. Never call `ensureThemeSync()` (wipes user settings) or overwrite host theme when usable.

## Conflicts / notes
- `onThemeChange` is a single global callback, not a multi-listener set — plugin cannot register its own without displacing host's. Plugin should use `getThemeEpoch()` polling or bindTheme instead. [primary, theme.ts:428-433]
- `setTheme(themeObject)` not supported (only by name); so plugins cannot push a Theme object to host via setTheme — must use `setThemeInstance`. [primary, extension-ui-controller.ts:185-191]

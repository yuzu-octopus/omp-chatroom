# Angle 3 — Plugin TUI vs host TUI gap analysis

Date: 2026-10-26. Sources: plugin repo `/home/yuzu/projects/omp-chatroom/plugin/src` and host `/home/yuzu/.bun/install/global/node_modules/@oh-my-pi/pi-tui`.

## Claims

- Plugin hand-rolls width budgeting (`fitWidth`, `fitBlock` in `plugin/src/panel/chrome.ts`) because host's `overlay-box` helpers under/over-fill rows; host provides `OverlayPanel`/`PanelRows`/`PanelDivider` (`pi-tui/src/chrome/overlay-box.ts:207-344`) which own rectangular framing and row memoization. Plugin does not use them. [primary]
- Plugin panel implements `Component` manually with string rows (`panel.ts:111`), while host custom messages use `FramedMessageComponent` (`pi-tui/src/chrome/message-frame.ts:60`) which handles renderer fallback, collapse, markdown, native describe. Plugin cards reimplement framing. [primary]
- Plugin's `bodyLines` (`cards/body-lines.ts`) mirrors host IRC `bodyLines` (`pi-tui/src/tools/wait.ts:655`) with same collapsed=3, expanded=12, width=100 constants. Aligned. One difference: plugin does not trim lines (deliberate for code). [primary]
- Plugin uses host chrome helpers `topBorderSplit`/`dividerSplit` (`chrome.ts:41,48`); these exist in host. OK. But computes `chatWidth - 2` for sidebarWidth, while host `splitDividerCol = sidebarWidth + 3` (`overlay-box.ts:59-61`) — off-by-constants risk. [primary]
- Plugin symbols: message cards use `theme.styledSymbol("tool.irc", "accent")` for IRC icon — matches host `ircGlyph` (`wait.ts:638`). Good. Claim card uses `theme.symbol("status.pending")` (not styled) for pending flag; host uses `styledSymbol` for tool icons. Minor inconsistency. [primary]
- Plugin defines `BOX_ROUND` liveTable from host `boxRound.*` keys (`host-theme.ts:597`) — good sourcing, avoids hardcoded glyphs. [primary]
- Host uses native describe (`card`, `col`, `md`, `span`, `row`, `text`) for TSP cards (`wait.ts`, `tool-activity.ts`); plugin tool-cards use `describeRoomCall`/`describeRoomResult` with `NativeToolView` and `toolHeadSpans` — aligned with host pattern. [primary]
- Host IRC cards use role `omp.irc.${kind}` and tone "info"; plugin message cards use custom types but host frame role `omp.custom`. Plugin does not set native role/tone on cards? Let's check: plugin tool-cards describe functions likely set tone. Message cards: frameComponent returns Component; does it call describe? Need check. [inference]
- Plugin's host-theme fallback is large (uncolouredTheme ~200 lines) duplicating every Theme member; host's own fallback maybe? Not found. This is defensive but maintenance burden. [primary]
- Plugin's `frameHintRow` uses `theme.sep.dot` and `theme.fg("dim", hint)` — host uses `keybinding-hints.ts` maybe. Let's check host keybinding hints. [primary]

## Hand-rolled that host provides
1. Panel container/layout → `OverlayPanel` + `PanelRows` + `splitRow`/`splitBodyWidth`.
2. Message frame → `FramedMessageComponent`.
3. Width fit → host `truncateToWidth`/`visibleWidth`/`padding` (already used) but wrapper fitWidth maybe unnecessary if using PanelRows.
4. Status line → host `renderStatusLine` (used in cards).
5. Body quote lines → host `bodyLines` pattern (plugin reimplements due to module-private).

## Wrong/inconsistent
- Width budget: `chatWidth - 2` passed as sidebarWidth to topBorderSplit; host expects sidebarWidth and computes divider at sidebarWidth+3. Need verify: if chatWidth is content width, sidebarWidth should be chatWidth+? Let's compute: splitBodyWidth(width, sidebarWidth)=width-sidebarWidth-7. Plugin's split: chat pane + board pane. Hard to know. Potential off-by. [inference]
- Color tone: claim card uses `theme.symbol` not styled; board STATE_TONE uses "success"/"warning"/"muted" (host tones). OK.
- Box chars: uses host boxRound via liveTable (good).
- Layout: Panel has no native describe; not in TSP tree? Host panels describe as col/row. Plugin's ANSI-only rows may not participate in native layout/expand. [inference]

## Do not change
- bodyLines constants aligned with host.
- styledSymbol("tool.irc","accent") for IRC icon.
- use of truncateToWidth/visibleWidth.

# F5 — Advantages of the room over native `agent://`: what it provides and why it matters

## Angle
What the room provides that native `agent://` / `agent://all` do not; evidence from literature and omp's own design that each matters.

## Claims

1. **Native `agent://` is point-to-point with a 4-outcome receipt and no shared object.** `IrcBus.send` → `IrcBridge.deliver()`; outcomes exactly `injected | woken | revived | failed` (`pi-tui/src/tools/irc.ts:27-31`). Broadcast is N independent sends, each with its own mailbox/session file/receipt; `agent://all` is explicitly write-only (`pi-coding-agent/src/internal-urls/agent-protocol.ts:209`). A late joiner cannot reconstruct the conversation. [primary, 2026-10-10 host tree 18.8.7]

2. **Native `IrcMessage` carries no priority, topic, TTL, lease, claim, or envelope fields** (`pi-tui/src/tools/irc.ts:7-24`). The room's `RoomRecord` carries `kind`, `seq`, `gen`, `ttlMs`, `dependsOn`, `waited`, `tier` etc. [primary]

3. **Native backpressure is one undifferentiated drop-oldest queue.** `MAILBOX_CAP = 100` (`bus.ts:31`); `if (mailbox.length > MAILBOX_CAP) { const dropped = mailbox.shift(); ... }` (`bus.ts:286-292`). No priority/backpressure/rateLimit/coalesce/tier grep hits across `src/irc/`, `src/tools/wait.ts`, `irc-bridge.ts`, `agent-registry.ts` (verified 2026-10-10). A tier-0 interrupt can be evicted to make room for a tier-2 post. [primary]

4. **Native `wait` refuses a peer-only wait.** `if (jobs.length === 0 && !serviceRunning) throw new ToolError("Nothing to wait for…")` (`wait.ts:90-94`); bus leg only reachable once something else is awaited (`wait.ts:114-118`); cap `WAIT_MAX_MS = 30*60_000` (`wait.ts:25`). No "block until peer X changes state / message arrives / resource free". [primary]

5. **No claim/lock/lease primitive exists in the host.** `builtin-names.ts` has no claim/lock/reserve/lease entry; grep for `claim|lease|lock` across `src/tools/*.ts` returns only unrelated identifiers (`blocks`, `answerImageBlocks`). `todo` is parent-owned, not a shared reservation. [primary]

6. **The room's claim board is first-writer-wins with mandatory TTL and logged reclaim.** `grant()` first-writer-wins, loss appends nothing (`claims.ts:38-44`); `isStale` = TTL expired OR holder parked/aborted (`claims.ts:24-31`); `reclaimIfStale` replaces + notifies previous holder; `expireStale` → `release{reason:"expired"}` → promote oldest waiter → T0 notice (`claims.ts:88-102`). No framework surveyed ships a lease (AG2, LangGraph, CrewAI, OpenAI SDK/Swarm, smolagents, Letta, Claude Code teams, Magentic-One, CAID) [large-swarm REPORT.md §2]. [primary]

7. **Tiered attention is the room's answer to the firehose.** `classify`: `@mention`/reply-to-your-message/your-lease-revoked → T0; followed topic/held claim/joined thread → T1; else T2 (`tiers.ts:19-42`); token bucket T0-exempt (`governor.ts:100`); per-turn T1 caps (`governor.ts:119-172`); coalesce (`governor.ts:205-217`). Native `MAILBOX_CAP` protects the wrong class (R2 finding). [primary]

8. **Three bounded blocking waits expressible only via the room.** `wait_for_agent` (timeout clamped, never throws, `useless:true` on timeout/aborted, `wait-for-agent.ts:82-92,126`); `wait_for_message`; `wait_for_claim` (timeout is normal outcome `acquired:false`, not error, `wait-for-claim.ts:26,74-91`). Native `wait` refuses peer-only waits (claim 4). [primary]

9. **Cold summary tree makes a bounded digest honest.** `viewPath`/`viewTiling`/`loadView` (`tree-store.ts:214-332`); `validateZoomRange`/`zoom` (`tree-store.ts:461-483`); single-writer compaction (`compactor.ts:11`); `room{op:"recall"}` regex over raw log (`room.ts:48`). Late joiner replays whole raw log or accepts summary with no route back; `zoom` keeps digest small while detail stays reachable (`REPORT-v3-tree.md:43-55`). This is the plugin's only LLM spend (`PLAN-build.md:2228-2246`). [primary]

10. **Claim-expiry sweep prevents squatted leases.** `room-store.ts:279-299` refcounted `ctx.setInterval` calling `expireStale` every `claimSweepMs: 5_000` (`config.ts:35`, `governor.ts:30`). Plan risk R31: "A claim held past its TTL can be squatted forever if nothing sweeps it." [primary]

11. **Bounded join digest + per-agent cursors.** `onboarding/digest.ts`, `hook.ts`, `cursors.ts`; each agent's read position is its own. Native `§ Coop` roster is a start-time snapshot of live peers only, absent in restricted children (`REPORT.md:124`, `REPORT-v2-hybrid.md:422`). Without per-agent cursors, one slow reader pins room context for everyone (`REPORT-v2-hybrid.md:324`). [primary]

12. **Tiered attention prevents the measured firehose.** Cohere first-party: with PIV prompt 84% of messages went workers→lead, worker-to-worker averaged <1 per task; planners' reports grew 17k→75k chars as workers 2→16 "while reward barely moved"; conclusion: "messages mostly repeated what the lead would have received in reports anyway" (`large-swarm REPORT.md` §3, Cohere source). Anthropic's own "Dynamic workflow size" setting is "an advisory guideline, not an enforced cap" — intra-corpus proof guidance cannot substitute for mechanics. [primary/secondary]

13. **Shared durable record survives sessions and resumes.** Log at `<ctx.cwd>/.omp-room` (not per-session `local://` — corrected from plan; `room-store.ts:210-222`). fsync JSONL. Native persistence is per-recipient: incoming record is `custom` entry `irc:incoming` in recipient's session JSONL (`irc-bridge.ts:195-205,232-240`); 10 recipients = 10 files, none is the room. [primary]

14. **Exclusive ownership prevents the most-reported failure.** 9 of 17 `anthropics/claude-code` issue bodies describe duplicate/racing work on same artifact — "the loser's work is silently overwritten" (`large-swarm REPORT.md` §3). Bun's 64-agent Zig→Rust port: agents ran `git stash`/`git stash pop`/`git reset HEAD --hard` stepping on each other. Cursor's staff: "parallel subagents sharing one working tree (no write-scope coordination), overlapping edits collided." AI-agent PRs conflict at 27.67% (142k+ agentic PRs) vs 0.2% humans. [primary/secondary]

15. **Shared-file lock protocols fail at scale (first-party evidence).** Cursor: "Our initial approach gave agents equal status and let them self-coordinate through a shared file… locking mechanism. This failed… Agents would hold locks for too long, or forget to release them entirely. Even when locking worked correctly, it became a bottleneck. Twenty agents would slow down to the effective throughput of two or three." Fix: abandon worker-to-worker coordination; planner owns plan, executor owns it, judge verifies; "Workers… don't communicate with any other planners or workers. They work on their own copy of the repo." (`large-swarm REPORT.md` §3, Cursor source). This is the strongest signal that a *peer-to-peer room* is not the whole answer — but it also shows why TTL+reclaim (not bare locks) is the room's distinguishing feature. [primary/secondary]

16. **Deadlock across wait mechanisms is a documented, reproduced failure.** oh-my-pi issue: two+ task agents `hub wait` on messages from each other stall for entire timeout (default 120s), no indication, status shows all "running", no error; root cause "graph is maintained on every wait() and consumed on every matching send(), but never inspected for cycles"; "a cycle can span more than one wait mechanism" (`large-swarm REPORT.md` §3). Plugin has three independent wait mechanisms — per-mechanism check misses cross-mechanism cycle. This motivates R4 (cycle detection over wait-for graph spanning all three). [primary]

17. **Coordination chatter is itself a measured failure mode.** Message density of a successful swarm saturates at ≈0.39 coordination messages per agent-turn (`large-swarm REPORT.md` §7, source [84]). Total reasoning turns grow super-linearly: `T = 2.72 × (n+0.5)^1.724`, R²=0.974. Multi-agent costs 3–10× single-agent tokens (Anthropic 2026 first-party). MAS consumes 4×–220× input tokens of single-agent across 9 datasets/4 frameworks (primary [82]). Room's T1/T2 tier split and 0.39 target are the practitioner measurement behind tiering. [primary/secondary]

18. **The room does NOT replace native steering — asymmetric strengths.** Native `agent://` parent→streaming child: `agent.steer(...,{steering:true})` hard steer mid-run (`irc-bridge.ts:220-227`). Non-parent→streaming: pushed to `#interrupts`, drained interrupt-before-aside at next step boundary (`irc-bridge.ts:26,67-71,228`). Idle non-main: `wakeForIrc([record])` real wake turn relayed to sender (`irc-bridge.ts:243,189`). Room bypasses bus entirely: delivery adapter calls `sendCustomMessage` with `deliverAs:"steer"` (T0) / `"aside"` (T1), cursor bump for T2 (`delivery.ts:60,67,35-37`). Per host rule (`agent-session.ts:8796-8798`): explicit `deliverAs` queues without starting a turn in either state; `aside` at idle starts a turn. Consequence: room T0 to idle agent is appended+persisted, no turn, no wake; room T1 to idle starts a turn. To wake/revive idle peer → use native `agent://`. [primary]

19. **Asymmetry that matters: interrupt intent ≠ interrupt strength.** Room T0 class (`@mention`, reply-to-your-message, your-lease-revoked — `tiers.ts:22-23,33`) computed per viewer; steers every agent it classifies, not just the intended one. Corrections/private/sensitive instructions → `agent://<id>` (one addressee, bounded blast radius, no shared record). Coordination → room post. [primary]

20. **Evidence is inference, not measurement.** No source studies a persistent multi-agent room, compares claim board vs free-form chat, or measures shared-state maintenance cost across agent turnover (`REPORT.md:311-313`, `REPORT-v2-hybrid.md:377-379`). Claim board is the one layer with both verified gap and adjacent measured support; chat/panel/cards/tree rest on inference (`PLAN-build.md:151-160`). Noise-floor protocol: config-equivalent coordination-inert protocols differ by [-3,+18] pp across two n=100 seeds; 7 of 10 recent MAS papers report headline gains below that envelope (`large-swarm REPORT.md` §6, source [13]). [primary]

## Conflicting evidence
- R2's tier table asserts T0 "yes (idle → wake; streaming → step-boundary interrupt)" (`REPORT-v2-hybrid.md:318-320`); implementation delivers hard steer to streaming agent and no turn to idle one. Doc/code gap, not settled semantic (`room-vs-native.md` §4). [primary]
- "Parallelism is faster" vs "multi-agent often takes longer" — thoroughness vs elapsed time; Anthropic Opus 4.8: 5-agent team 85.4% vs single 84.3%, "using just 20% of the latency", but no speedup on easiest problems (coordination overhead offsets parallelism gains). [primary]

## Gaps
- No measured study of a persistent multi-agent room exists; revisit triggers listed in `room-vs-native.md` §5. [primary]
- Tier distribution (T0/T1/T2) is unmeasurable: tier computed per-viewer at delivery, never stored (`large-swarm REPORT.md` §6). [primary]
- Wait outcomes not recorded (waiter queue in-memory; `wait_for_claim` returns tool result, never a record). [primary]
- No `member{action:"leave"}` record emitted; digest changed to "1 joined · N live". [primary]

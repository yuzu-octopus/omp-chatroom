# F1 — AG2 / AutoGen (Microsoft): coordination primitives, defaults, documented group-chat limits

## Angle

What coordination primitives AG2/AutoGen actually gives a multi-agent team; defaults; documented limits of group chat.
Scope: AG2 classic `GroupChat`/`GroupChatManager`; AG2 patterns API (`initiate_group_chat`); AG2 `ag2.network` WorkflowAdapter (the "later" successor); AutoGen v0.4 AgentChat teams (`RoundRobinGroupChat`, `SelectorGroupChat`, `Swarm`, `MagenticOneGroupChat`); AutoGen arXiv 2308.08155 §A5/C.1/C.2; Magentic-One report 2411.04468. Code executors and nested chats included.

## Claims

- **Problem group chat is documented to solve (AG2 classic):** "The core idea of group chat is that all agents contribute to a single conversation thread and share the same context. This is useful for tasks that require collaboration among multiple agents." Manager picks one speaker → speaker responds → manager **broadcasts** to all. / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/ / fetch 2026-10-20 / primary
- **Speaker selection (AG2 classic `GroupChat`):** five strategies — `auto` (**default**, manager's LLM picks), `round_robin` (order given), `random`, `manual` (human), or a **callable** that returns the next agent or `None` to end the chat. / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/ and https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/ending-a-chat/ / fetch 2026-10-20 / primary
- **Selection uses agent `description` (not `system_message`)** for the LLM picker; without a `description` the manager falls back to `system_message`, "which may be not be the best choice". / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/ / fetch 2026-10-20 / primary
- **`max_round` semantics (AG2 classic):** limit on number of agent replies; "Each round represents an agent speaking and includes the initial message" (i.e. the initial speaker's message counts as round 1). `max_turns` is the two-agent analogue (round trip of both agents). / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/ending-a-chat/ / fetch 2026-10-20 / primary
- **Documented control limit (AG2 classic):** "Group chat is a powerful conversation pattern, but it can be hard to control if the number of participating agents is large." Mitigation shipped = `allowed_or_disallowed_speaker_transitions` (per-agent allow/deny lists) + `speaker_transitions_type` ("allowed"/"disallowed"). / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/ / fetch 2026-10-20 / primary
- **Identity invariant:** all agents in a `GroupChat` must have unique names; duplicates raise `ValueError` (so speaker selection and message routing work). / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/groupchat/ / fetch 2026-10-20 / primary
- **Shared state in AG2 classic:** the shared artifact is the *message thread* (broadcast). A separate shared mutable dict `context_variables` is threaded through the group chat — `initiate_group_chat(...)` returns `(result, context_variables, last_agent)`; `AutoPattern`/`ManualPattern` accept a `context_variables` argument. / https://classic.docs.ag2.ai/latest/docs/user-guide/basic-concepts/introducing-group-chat/ and https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/ / fetch 2026-10-20 / primary
- **Termination inventory (AG2 classic, one page, seven routes):** (1) max turns; (2) agent `is_termination_msg`; (3) `max_consecutive_auto_reply`; (4) human replies `exit`; (5) group chat has no next agent (custom callable returns `None`); (6) transition to `TerminateTarget` (also: `RevertToUserTarget` with no `user_agent` ends the chat); (7) custom reply function returning `(True, None)`. / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/ending-a-chat/ / fetch 2026-10-20 / primary
- **AG2 current patterns API (post-0.9):** orchestration is expressed as a *pattern* object + `initiate_group_chat(pattern=..., messages=..., max_rounds=10)`. Presets: `DefaultPattern`, `AutoPattern` (LLM manager selects next speaker from context + agent descriptions), `RoundRobinPattern`, `RandomPattern`, `ManualPattern`. Plural `max_rounds` here vs classic `max_round`. / https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/ and https://classic.docs.ag2.ai/latest/docs/user-guide/basic-concepts/introducing-group-chat/ / fetch 2026-10-20 / primary
- **Swarm folded into group chat:** "As of version 0.9, we have merged the experimental Swarm functionality into the core framework, creating a new way to run group (multi-agent) chats. The new group chat contains all of the functionality available in the Swarm (and more)." / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/orchestrations/ / fetch 2026-10-20 / primary
- **AG2 orchestration pattern catalogue (classic):** two-agent chat, sequential chat (carryover of summary into next chat), group chat, **nested chat** ("a mechanism to package a workflow into a single agent/chat for reuse in a workflow"). / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/orchestrations/ / fetch 2026-10-20 / primary
- **Code executors (AG2 classic):** `UserProxyAgent(code_execution_config={"executor": LocalCommandLineCodeExecutor(work_dir=..., timeout=60)})`; `use_docker=True` runs generated code in Docker. / https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/code-executors/ and https://classic.docs.ag2.ai/latest/docs/user-guide/advanced-concepts/groupchat/custom-group-chat/ / fetch 2026-10-20 / primary (code-executor page existence confirmed via search result title; body not read in detail)
- **AutoGen v0.4 AgentChat team presets:** `RoundRobinGroupChat`, `SelectorGroupChat`, `MagenticOneGroupChat`, `Swarm`. "A team is a group of agents that work together to achieve a common goal." / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html / fetch 2026-10-20 / primary
- **Documented team-usage limit (AutoGen v0.4):** "Teams are for complex tasks that require collaboration and diverse expertise. However, they also demand more scaffolding to steer compared to single agents. … start with a single agent for simpler tasks, and transition to a multi-agent team when a single agent proves inadequate." / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html / fetch 2026-10-20 / primary
- **`RoundRobinGroupChat`:** all agents share the same context; each turn's response is broadcast to all other agents ("ensuring that the entire team maintains a consistent context"). / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html / fetch 2026-10-20 / primary
- **`SelectorGroupChat` mechanism:** a generative model selects the next speaker from shared conversation context + each participant's `name` and `description`; the selected agent's reply is broadcast to all participants; termination condition is then checked. Default: **no consecutive turns by the same speaker** unless it is the only agent available (`allow_repeated_speaker=True` disables). Overrides: `selector_func` (bypasses model entirely; may return `None` to fall through), `candidate_func` (narrows candidate set; must be non-empty), `selector_prompt` with `{participants}`, `{roles}`, `{history}` placeholders. / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html and https://microsoft.github.io/autogen/stable/reference/python/autogen_agentchat.teams.html / fetch 2026-10-20 / primary
- **Selector implementation detail (source):** selection retries up to `max_selector_attempts`, feeding back "No valid name was mentioned. Please select from: …" when the model names no participant; `candidate_func` result replaces the default previous-speaker-excluded candidate list entirely. / https://microsoft.github.io/autogen/stable/_modules/autogen_agentchat/teams/_group_chat/_selector_group_chat.html / fetch 2026-10-20 / primary
- **Documented scaling limit on the selector (AutoGen v0.4):** "Try not to overload the model with too much instruction in the selector prompt." For GPT-4o one may write per-agent conditions; for smaller models (Phi-4) keep it minimal. "Generally, if you find yourself writing multiple conditions for each agent, it is a sign that you should consider using a custom selection function, or breaking down the task into smaller, sequential tasks." / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html / fetch 2026-10-20 / primary
- **Termination conditions are composable in v0.4** with `|`: `TextMentionTermination`, `MaxMessageTermination(max_messages=25)`, `ExternalTermination` (graceful — stops after the current agent's turn so state stays consistent), `HandoffTermination(target="user")`; plus team-level `max_turns`. Example stop_reason strings: "Text 'APPROVE' mentioned", "External termination requested", "Maximum number of messages 2 reached". / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html and .../selector-group-chat.html and .../swarm.html / fetch 2026-10-20 / primary
- **`Swarm` (v0.4):** no central orchestrator; the next speaker is determined by the most recent `HandoffMessage`; all agents still share one message context; "This enables agents to make local decisions about task planning, rather than relying on a central orchestrator such as in `SelectorGroupChat`." Handoff is produced via tool calling, so the model must support tool calling; **parallel tool calling can produce multiple handoffs → "unexpected behavior"**, mitigations: disable `parallel_tool_calls`. If multiple handoffs are detected, only the first is executed. / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/swarm.html and https://microsoft.github.io/autogen/stable/_modules/autogen_agentchat/agents/_assistant_agent.html / fetch 2026-10-20 / primary
- **Shared state in v0.4:** teams are stateful — conversation context is kept within the team and all participants between runs; `reset()` clears team + participants (`on_reset()`), `run()` with no task continues the previous context. Persistence = `save_state()`/`load_state()` on agent and team (JSON-serialisable `TeamState` with `agent_states` map, `message_thread`, `current_turn`, `next_speaker_index`); per-agent `AssistantAgent` state is exactly its `model_context` (LLM messages). Note the state dump is keyed by `agent_id` and includes a `message_buffer`. / https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/state.html and .../tutorial/teams.html / fetch 2026-10-20 / primary
- **Token/context growth (v0.4 source):** default `model_context` for `AssistantAgent` and for `SelectorGroupChatManager` is `UnboundedChatCompletionContext` — history grows without bound unless the user opts in. Documented mitigations: `BufferedChatCompletionContext(buffer_size=N)` ("limit the number of recent messages sent to the model … useful when the model has a limit on the number of tokens it can process") and `TokenLimitedChatCompletionContext` ("limit the number of tokens sent to the model"), or a custom `ChatCompletionContext`. / https://microsoft.github.io/autogen/stable/_modules/autogen_agentchat/agents/_assistant_agent.html and https://microsoft.github.io/autogen/stable/_modules/autogen_agentchat/teams/_group_chat/_selector_group_chat.html / fetch 2026-10-20 / primary
- **AG2 network (`ag2.network` WorkflowAdapter) is the declared successor to `GroupChat`:** classic → network mapping table (`GroupChat`→workflow channel; `GroupChatManager`→`WorkflowAdapter`+`Hub`; `Agent.handoffs`→per-channel `TransitionGraph`; `max_round=N`→`TransitionGraph(max_turns=N)` "Same hard cap"). Stated differences: "The hub is authoritative. Turn-taking, state, audit, and expectation enforcement all live in the hub"; channels have ids (audit/replay/inspection scoped to a channel); WAL (`hub.read_wal`) + audit log; "Expectations replace `max_round` exhaustively" — e.g. `reply_within(60s, auto_close)` per channel type with violations logged to the audit log and auto-close; "Views replace ad-hoc context windowing" (default `FullTranscript`, or `WindowedSummary`); transport is pluggable (`LocalLink` in-process default, cross-process/cross-host transports drop-in). / https://docs.ag2.ai/docs/user-guide/network/migration_from_group_chat/ / fetch 2026-10-20 / primary
- **AG2 network deadline/liveness primitives (defaults):** `consulting` = `acks_within(30s, auto_close)`, `reply_within(600s, auto_close)`; `conversation` = `max_silence(3600s, audit)`; `discussion` = `turn_within(120s, warn)`, `turn_within(600s, hide)`; `workflow` = `turn_within(120s, warn)`, `turn_within(600s, auto_close)`. Channel lifecycle includes a TTL sweeper (`ACTIVE → CLOSED (TTL expired)`) and auto-close on expectation violation. / https://docs.ag2.ai/docs/user-guide/network/adapters_overview/ / fetch 2026-10-20 / primary
- **AG2 network context-window policy (documented token cost):** built-in views `FullTranscript()` (every visible envelope), `WindowedSummary(recent_n=N)` (last N; prepends a `CompactionSummary` counting elided turns), `NamedTranscript()`, `NamedWindowedSummary(recent_n=N)` (adds `[<sender name>]:` prefixes). "This keeps the LLM's behaviour grounded in long-running discussions without exploding the token budget." Audience is honoured per view (an envelope addressed to one participant is invisible to others). Heuristics: short exchange → `FullTranscript`; long discussion → `WindowedSummary` tuned to participant count and turn density; specialists that should ignore chatter → custom view filtering by audience/tags. / https://docs.ag2.ai/docs/user-guide/network/views_and_skills/ / fetch 2026-10-20 / primary
- **Why N-party channels need sender labels (AG2 network):** "In a 3+ party channel (discussion, workflow), every non-self envelope collapses into the same `role: "user"` stream. Without a sender label the LLM can't tell which peer said which message." / https://docs.ag2.ai/docs/user-guide/network/views_and_skills/ / fetch 2026-10-20 / primary
- **AG2 network documented gaps (roadmap):** `LLMCondition` (declarative LLM-conditioned routing), `NestedChatTarget` (first-class sub-flow target), **parallel dispatch** ("fan out to multiple speakers within a single workflow turn, gather their replies, advance once all are in"), auto-merge of tool-return fields into context, `AllOf`/`AnyOf` condition composers. Pattern cookbook status: Pipeline/Clean, Coordinator/Clean, Escalation/Clean, Feedback Loop/Clean, Triage-with-Tasks/Clean, Hierarchical/Partial, Redundant/Partial ("No parallel dispatch; one specialist at a time"), Context-Aware Routing/Partial ("routing reasoning lives inside the coordinator's LLM, not the framework"). / https://docs.ag2.ai/docs/user-guide/network/pattern_cookbook/pattern_cookbook/ / fetch 2026-10-20 / primary

## Conflicting evidence

- **View default for N-party AG2 channels.** `views_and_skills` states the built-in view table default for `discussion`/`workflow` is `NamedWindowedSummary(recent_n=N)`; `adapters_overview` "Default View Policies" table lists `WindowedSummary(recent_n=N*2)` for both (and `WindowedSummary(recent_n=10)` for `conversation`). Both pages are official AG2 docs, same site, same fetch date — unresolved doc inconsistency. / https://docs.ag2.ai/docs/user-guide/network/views_and_skills/ vs https://docs.ag2.ai/docs/user-guide/network/adapters_overview/ / primary
- **Round/turn parameter naming.** Classic API `max_round` (singular, counts agent replies including the initial message) vs patterns API `max_rounds` vs `initiate_chat(max_turns=)` (round trips) vs `initiate_group_chat(max_rounds=)` vs network `TransitionGraph(max_turns=N)` and `BaseGroupChat(max_turns=...)`. Four different names/granularities for "stop after N". / multiple AG2 + AutoGen docs pages listed above / primary
- **"Termination" granularity differs between generations.** Classic ends a group chat when there is *no next agent* (callable returns `None`) or a `TerminateTarget` transition; v0.4 AgentChat ends on composable `TerminationCondition`s (`TextMentionTermination`, `MaxMessageTermination`, `ExternalTermination`, `HandoffTermination`) plus team `max_turns`. `ExternalTermination` is explicitly *graceful* (current agent finishes its turn first) while `CancellationToken` is explicitly *not* (may leave the team in an inconsistent state and not reset the termination condition). / https://microsoft.github.io/autogen/stable/reference/python/autogen_agentchat.teams.html / primary
- **Group chat is presented as both the default and the thing to avoid.** AG2 classic calls group chat "a more general conversation pattern" and the recommended starting point ("Consider using the two-agent chat or the group chat setup first"), while the same classic page says it "can be hard to control if the number of participating agents is large", and AutoGen v0.4's teams page says teams "demand more scaffolding to steer compared to single agents". Not a factual contradiction, but the vendor docs never resolve at which swarm size group chat stops being the right primitive. / primary
- **`Swarm` vs AG2 classic Swarm are different lineages.** AutoGen v0.4 `Swarm` is a team type documented as "A multi-agent design pattern first introduced by OpenAI in Swarm"; AG2 separately merged *its own* experimental Swarm into core group chat as of v0.9. Same name, different implementations, no cross-reference between the two docs sites. / primary

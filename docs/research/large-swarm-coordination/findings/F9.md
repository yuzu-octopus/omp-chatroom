## Claims

### (a) Topology

- **No single topology wins across tasks; the winner is task-dependent.** MacNet compares chain/tree/graph × 6 sub-topologies over MMLU, HumanEval, SRDD, CommonGen-Hard: "a chain topology is more suitable for software development, while a tree topology is ideal for creative writing… no single topology consistently excels across all tasks." / https://arxiv.org/abs/2406.07155 / 2026-10-20 / primary
- **Density helps on average, but irregular beats regular.** MacNet: "the densely connected mesh topology outperforms the moderately dense tree topology, which in turn outperforms the sparsely connected chain topology" — yet "despite the intuitive appeal of densest interactions (i.e., mesh), they do not always yield optimal performance. In contrast, irregular topologies often demonstrate statistically significant advantages" (hypothesised cause: information overload from over-dense interaction). Random topologies "consume approximately 51.92% less time than mesh topologies". / https://arxiv.org/abs/2406.07155 / 2026-10-20 / primary
- **Direction matters: divergent > convergent.** MacNet: "reversing the directions of specific topologies can lead to significant performance degradation. Typically, divergent topologies… substantially outperform their convergent counterparts" — convergent aggregation at one node is hard; recommendation is "maximize divergence while minimizing convergence". / https://arxiv.org/abs/2406.07155 / 2026-10-20 / primary
- **Centralized (hub-and-spoke with an orchestrator) wins on decomposable tasks and contains errors; Independent (no inter-agent comms) is the worst and amplifies errors 17.2×.** Google/MIT "Towards a Science of Scaling Agent Systems", 260 configs × 6 benchmarks × 5 architectures (SAS, Independent, Centralized, Decentralized, Hybrid) × 3 LLM families: trace-level error amplification A_e^trace = 1.0 (SAS) / 4.4 (Centralized) / 7.8 (Decentralized) / 5.1 (Hybrid) / 17.2 (Independent, 95% CI [14.3, 20.1]); Centralized contains it to 4.4× (CI [3.8, 5.0]) "by enforcing validation bottlenecks that intercept errors before aggregation". / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **Headline topology range: +80.8% to −70.0% relative to a single agent.** Same paper: "Relative performance change compared to single-agent baseline ranges from +80.8% on decomposable financial reasoning to −70.0% on sequential planning." Per-benchmark: Finance Agent all MAS +57% to +80.8%; PlanCraft all MAS −70% to −39%; BrowseComp-Plus Independent −35% while structured coordination gains modestly; Workbench −11% to +6%; SWE-bench Verified all MAS −15% to −2%; Terminal-Bench Independent +2%, Centralized −19%. "Optimal architectures vary systematically: decentralized coordination benefits tasks requiring parallel exploration of high-entropy search spaces (dynamic web navigation: +9.2%), while all multi-agent variants universally degrade performance on tasks requiring sequential constraint satisfaction (planning: −39% to −70%)." / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **Coordination overhead is a real, measurable tax that is NOT explained by error amplification.** Same paper: overhead Independent 58%, Decentralized 263%, Centralized 285%, Hybrid 515% relative to SAS (1.6–6.2× token budgets). Three regimes: under-coordination (O<100%: ΔS≈+2–4%), optimal band (200%<O<300%, Ec≈0.16, dominated by Centralized/Decentralized), over-coordination (O>400%, Ec≈0.11, Hybrid; coordination-failure modes 12.4% vs 0% Independent / 1.8% Centralized / 3.2% Decentralized). Crucially: "neither the main effect of error amplification (β̂=0.014, p=0.658) nor its interaction with tool count (β̂=0.022, p=0.332) reaches statistical significance… the dramatic performance differences across architectures… are better explained by other coordination mechanisms, particularly efficiency (E_c) and overhead (O%)". / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **Redundancy has an interior optimum, not a monotone "more is better".** Same paper: work redundancy ρ ranges 0.41 (Centralized median) to 0.50 (Decentralized); ρ>0.50 correlates negatively with success (r=−0.136, p=0.004); "optimal redundancy occurs at R≈0.41… balancing information fusion with reasoning independence". Also, high-performing runs show more shared-token entropy (≈1.8 bits, p<0.001) and less contradictory mass (median 2.3% successes vs 8.1% failures). / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **Star and tree topologies measurably FAIL to beat a single agent.** AgentPrune, five gpt-4-based agents, MMLU: Vanilla 82.14; Chain 82.35 (+0.21); Star 80.79 (−1.35); Tree 81.89 (−0.25); Layered Graph 78.41 (−3.73); Complete Graph 83.15 (+1.01); Random Graph 83.76 (+1.62); GPTSwarm 83.98 (+1.84); LLM-Debate 83.69 (+1.55); PHP 83.45 (+1.31); DyLAN 80.16 (−1.98). Authors' Obs.1: "certain topologies, such as star/tree structures, fail to consistently improve performance for multi-agent systems, even resulting in performance drops of 0.17% ∼ 3.97%." / https://arxiv.org/abs/2410.02506 / 2026-10-20 / primary
- **Pruning communication edges beats dense topologies on cost and on quality.** AgentPrune: 28.1%–72.8% token reduction when plugged into existing frameworks; MMLU $5.6 vs $43.7 for SOTA topologies; GSM8K AgentPrune-C 95.62 (+10.22), AgentPrune-R 95.83 (+10.43) vs Vanilla 85.40. Pruned graphs recover a role structure: "the Critic has a high number of incoming edges, while the Knowledge Expert has a high number of outgoing edges"; on HumanEval the outer edges of the standard code-completion workflow are retained; the Bug Fixer ends with no outgoing edges. GPTSwarm+AgentPrune: MMLU prompt tokens 3,055,230 → 990,312 (32.4%), $47.60 → $23.05, accuracy 83.98 → 83.05. / https://arxiv.org/abs/2410.02506 / 2026-10-20 / primary
- **Communication topology is itself learnable, and the learned topology ≈ task-specific structure.** GPTSwarm optimizes the inter-agent edge set by REINFORCE over DAGs: Mini Crosswords accuracy 0.465 (±0.0509) → 0.575 (±0.0275) after 10 iterations; with node optimization after edge optimization, 0.668 (±0.0060). On MMLU with 3 truthful + 3 adversarial agents, the optimized swarm beats Multiagent Debate (0.5751) at 0.8301 accuracy with 1.82 USD inference cost vs DyLAN's 0.8366 at 14.99 USD. / https://arxiv.org/abs/2402.16823 / 2026-10-20 / primary
- **Dynamic topology + dynamic team composition is the best-supported combination, and it beats both static topology and single-agent baselines.** DyLAN: "DyLAN realizes an 10.2% improvement to LLM Debate in terms of accuracy, with 10.6% lower #API calls"; "DyLAN has a better performance with only 36.6% API calls of LLM Debate and 35.1% of LATS on CG and <6% on DM". On GPT-4-0613 code generation: DyLAN 92.1 Pass@1 (+3.7 over single execution) at 15.94 API calls, vs MetaGPT 85.9 (−3.5) at >30 calls, AgentVerse 89.0 (+0.6) at 27 calls, LATS 94.4 at >40 calls, Reflexion 91.4 at 7.32 calls. / https://arxiv.org/abs/2310.02170 / 2026-10-20 / primary
- **DyLAN ablation isolates the two dynamic components.** Removing agent team reformation: code generation 82.9 → 76.2 Pass@1, decision-making 68.3 → 66.0. Removing early stopping: API calls 7.15 → 13.00 (AR), 4.39 → 13.00 (GR), 16.85 → 19.00 (CG), 24.85 → 54.25 (DM) with only slight accuracy change — i.e. "early-stopping… boosts efficiency to a great extent… while providing slight performance improvement. Agent team reformation, however, is critical to enhance the correctness of the final answer." / https://arxiv.org/abs/2310.02170 / 2026-10-20 / primary
- **Failure attribution from logs alone is unreliable — the best method gets the right agent only ~53–57% of the time and the right step ~14%.** Who&When dataset: 127 LLM multi-agent systems (algorithm-generated + Magentic-One), 184 distinct failure-annotation tasks, 30.9/30.2/23.2 human-hours for 3 annotators per pass, 15–30% uncertain annotations. Best method 53.5% agent-level accuracy, 14.2% step-level; "some methods performing below random" — all-at-once scores 12.50% step-level vs random 19.06% (algorithm-generated). "Even SOTA reasoning models, such as OpenAI o1 and DeepSeek R1, fail to achieve practical usability." Hybrid (all-at-once → step-by-step) = 57.02% agent / 12.28% step at 149,177 tokens. All three methods degrade with context length; "as context length reaches its maximum, all three failure attribution methods converge to near 0%". / https://arxiv.org/abs/2505.00212 / 2026-10-20 / primary
- **Topology-specific failure profiles differ per framework — one-size-fits-all does not hold.** MAST: "AppWorld frequently suffers from premature terminations (FM-3.1), potentially due to its star topology and lack of a predefined workflow making termination conditions less obvious"; OpenManus → step repetition (FM-1.3); HyperAgent → step repetition + incorrect verification. "These system-specific profiles underscore that there is no one-size-fits-all solution to MAS failures." / https://arxiv.org/abs/2503.13657 / 2026-10-20 / primary

### (b) Role assignment

- **Measured contribution beats human-prior role assignment, and human-prior assignment can be WORSE than random.** DyLAN Table 13 (7 candidate agents, 5 MMLU subjects, GR task): no optimization 63.5; Random Selection 64.8 (+1.3); Human Prior Selection (GPT-4 mimicking a human) 66.7 (+3.2); Agent Importance Score 73.6 (+10.1). On code generation: no optimization 76.2 (23.04 API calls), Random 75.6 (−0.6, 17.73 calls), Human Prior 78.0 (+1.8, 16.37 calls), Agent Importance Score 82.9 (+6.7, 16.85 calls). "In High School Statistics, Clinical Knowledge, and Public Relations subjects… prior selection performs even worse than random selection." Agent Importance Score needs almost no data: 1% of the optimisation set already gives GR 68.9 / CG 79.3; 10% gives 72.2 / 82.3; 100% gives 73.6 / 82.9. / https://arxiv.org/abs/2310.02170 / 2026-10-20 / primary
- **The optimal number of agents is small, and composition beats count.** DyLAN: "DyLAN with an optimized team of 3 agents can outperform both DyLAN before team optimization and LLM Debate with 4 agents" with efficiency +52.9% and +67.8%. Composition table (writers/reviewers): 6/6 → 76.2, 4/4 → 82.9, 4/3 → 81.1, 4/2 → 77.4, 3/3 → 78.0, 3/2 → 75.6 — "reviewers affect the performance slightly greater than writers… indicating the necessity of the amount of reviewers for code refinement." Per-subject gains from re-composed teams reach 25.0 pp (college mathematics 40.0 → 65.0). / https://arxiv.org/abs/2310.02170 / 2026-10-20 / primary
- **The best PROPOSER is not the best AGGREGATOR — role specialisation is measurable and non-trivial.** Mixture-of-Agents, AlpacaEval 2.0 LC win rate, 2 layers, Qwen1.5-110B as aggregator: as aggregator — Qwen1.5-110B 61.3, Qwen1.5-72B 59.3, WizardLM-8x22B 52.9, Mixtral-8x22B 48.4, LLaMA-3-70B 45.0, dbrx 41.5. As proposer — WizardLM-8x22B 63.8, LLaMA-3-70B 60.6, Qwen1.5-110B 56.7, dbrx 55.1, Mixtral 54.8, Qwen1.5-72B 53.3. "WizardLM demonstrated excellent performance as a proposer model but struggled to maintain its effectiveness in aggregating responses from other models." / https://arxiv.org/abs/2406.04692 / 2026-10-20 / primary
- **Role/trait COMPOSITION does not matter; the interaction pattern does.** MachineSoM (social-psychology view), 3-agent societies differing only in easy-going vs overconfident traits, MATH/MMLU/Chess: "distinct societies composed of 3 agents possessing varied traits play an indistinctive role in shaping performance" (significance tests insignificant); extending to 2–10 agents, "the impact of societies on performance remains indistinctive". What DOES matter: "Permutation of thinking patterns is crucial… debate-initial and debate-dominant strategies exhibit superiority" and "Employing uniform thinking patterns across all agents within a round of collaboration enhances efficiency. Besides, merely increasing the number of agents or the number of collaboration rounds does not consistently yield better outcomes." Only consensus-reachability differed by society (all-easy-going reaches consensus more often). / https://arxiv.org/abs/2310.02124 / 2026-10-20 / primary
- **Role assignment must be enforced by prompt scaffolding or agents will drift.** CAMEL: role-playing via inception prompting; named failure modes observed in the wild are "role flipping, assistant repeating instructions, flake replies, and infinite loop of messages"; the prompt must contain "Never flip roles! Never instruct me!" and "Never forget you are a <role> and I am a <role>". A Critic-in-the-Loop agent is added "to enhance the controllability of the role-playing framework… tree-search-like decision-making". Role-playing solutions beat single-shot gpt-3.5-turbo in both GPT-4 and human evaluation; CAMEL-7B (LLaMA-7B fine-tuned on the generated data) reaches HumanEval pass@1 14.0 / pass@100 57.9 vs LLaMA-7B 10.5 / 36.5 and Vicuna-7B 11.0 / 42.9. / https://arxiv.org/abs/2303.17760 / 2026-10-20 / primary
- **Sub-agent capability matters more than orchestrator capability.** Google/MIT: "In centralized architectures, configurations with high-capability sub-agents outperform those with high-capability orchestrators across all model families"; and, model-family-dependently, heterogeneous mixing helps Anthropic (low-capability orchestrator + high-capability subagents 0.42 vs homogeneous high-capability 0.32, +31%) but DEGRADES OpenAI and Gemini. / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **Role prompts are a cheap, high-yield intervention.** MAST intervention case study: "improving agent role specifications alone yields a +9.4% success rate increase for ChatDev with the same user prompt and LLM (GPT-4o)"; separately, "a straightforward system workflow adjustment ensuring the CEO had the final say contributed to a +9.4% increase in overall task success rate" (the paper uses 9.4% for two different interventions — see Conflicting evidence). Disobeying role spec is FM-1.2, 1.5% of failures. / https://arxiv.org/abs/2503.13657 / 2026-10-20 / primary
- **Coordination protocol classes (rule-based / role-based / model-based; static vs dynamic) each have a named cost.** MAC survey: Static = "ensures consistent task execution… relies on accurate initial design and domain knowledge… Fixed channels may deal with scalability and flexibility" problems; Dynamic = "adaptable roles and channels based on task needs" but "higher resource usage due to real-time adjustments"; Centralized = "simple to design and implement… efficient resource allocation" but "if the central node fails the entire system might collapse"; Decentralized = "system can continue functioning" but "inefficient resource allocation"; Role-based strategy = "modularity and reusability" but "rigid structure… performance relies on agents' connection level"; Model-based = "adaptability to dynamic env… robust to uncertainties" but "computationally expensive". (Survey = primary for its own taxonomy; secondary for the underlying experiments.) / https://arxiv.org/abs/2501.06322 / 2026-10-20 / primary (taxonomy) / secondary (as a summary of others' results)

### (c) Shared vs private memory

- **BOTH private and shared win — but the flat shared store alone LOSES to no memory at all.** CoMem component ablation (ALFWorld / PDDL success rate): AutoGen — private-only 83.58 / 62.41; collective-only 85.07 / 65.10; both 88.31 / 74.44. DyLAN — private-only 80.25 / 59.17; collective-only 77.61 / 67.22; both 87.31 / 69.50. "On AutoGen with PDDL, the full configuration achieves 74.44, surpassing collective-only (65.10) and personal-only (62.41)… removing the collective layer leads to a 12.03-point drop… while removing the private layer causes a 9.34-point drop… the private layer providing a slightly stronger safeguard against memory pollution." / https://arxiv.org/abs/2609.15009 / 2026-10-20 / primary
- **A flat shared memory repository is often WORSE than having no memory.** CoMem Table 1, PDDL column vs No-memory baseline: under DyLAN, G-Memory 59.53 vs no-memory 67.78 (−8.25); MetaGPT 52.80 (−14.98); MemoryBank 50.92 (−16.86); Voyager 58.17 (−9.61). Under AutoGen PDDL: MemoryBank 53.45 (−16.07), Generative 61.29 (−8.23), Voyager 67.60 (−1.92). Named mechanisms: "noise accumulation" (unverified trial-and-error floods the store) and "behavioral homogenization" (role-specific trajectories averaged out, lim_{t→∞} H(π_{a_i} || π_{a_j}) = 0). CoMem itself beats no-memory on every framework: average absolute gains +8.02 ALFWorld, +4.70 PDDL. / https://arxiv.org/abs/2609.15009 / 2026-10-20 / primary
- **Per-agent private memory beats centralized shared memory, and the gap widens as coordination gets less predictable.** DecentMem (per-agent dual-pool: exploitation pool of consolidated trajectories + exploration pool of LLM-generated candidates, online-routed by LLM-as-judge feedback): best average accuracy in 14 of 15 (backbone × framework) cells; average relative improvement 8.6% over the strongest centralized baseline (G-Memory) and 26.1% over no-memory, up to 52.5% (Qwen3-4B + AgentNet). Concrete averages: Qwen3-8B/AgentNet — no-memory 45.70, G-Memory 55.00, DecentMem 67.77; Qwen3-4B/DyLAN — 40.28 / 44.63 / 50.15; Qwen3-4B/AutoGen — 43.79 / 52.39 / 54.71; Gemma4-E4B/DyLAN — 57.65 / 64.86 / 67.05. Stochasticity sweep (AutoGen→DyLAN→AgentNet): margin over centralized 2.7% / 9.2% / 23.1% (Qwen) and 1.7% / 3.9% / 6.8% (Gemma) — "when coordination is less predictable, centralized memory homogenizes agent behavior more aggressively, and preserving per-agent experience matters more." Token cost: −32% / −49% / −47% vs G-Memory (43% avg) while improving accuracy; self-evolution convergence ~2.5× faster on DyLAN. / https://arxiv.org/abs/2605.22721 / 2026-10-20 / primary
- **Naive shared memory (share everything) actively HURTS accuracy; a gated/admitted shared memory helps.** Learning to Share, GPT-5.1, three parallel AutoGen/Magentic-One teams: AssistantBench accuracy / runtime — no shared memory 24.0 / 1389s; share-all 23.0 / 784s; LLM-filtered 25.7 / 856s; learned selective 26.7 / 882s. GAIA — no shared memory 47.9 / 1005s; share-all 44.2 / 967s; LLM-filtered 45.8 / 853s; learned selective 49.1 / 792s. "naively admitting all intermediate steps… yields reduced runtime but a drop in task accuracy, indicating that unfiltered memory can introduce irrelevant or misleading information into team contexts." Admission stats: share-all 100% of steps stored / 25.8% recall / 66.0% cross-team recall; LLM-filtered 44.4% / 18.0% / 66.6%; learned 84.9% / 22.2% / 69.0%. / https://arxiv.org/abs/2602.05965 / 2026-10-20 / primary
- **Shared memory + admission policy also buys wall-clock, and the gain survives scaling the number of teams.** LTS, Qwen3-32B: AssistantBench 14.7 → 20.3 with runtime 2239s → 1479s (−40.8%); GAIA 24.8 → 30.4 with runtime 1569s → 892s (−55.0%). Team-count sweep on GAIA (controller NOT retrained): memory-free M1-Parallel K=2 23.0/1161s, K=5 25.4/2034s, K=10 22.4/3411s (non-monotonic — more teams HURT the memory-free baseline); LTS 28.5/828s, 31.6/1234s, 29.1/2521s. / https://arxiv.org/abs/2602.05965 / 2026-10-20 / primary
- **Memory depth/width are interior optima, and the optimum is task- and framework-dependent.** CoMem: retrieval depth k∈{1,3,5,7} — AutoGen ALFWorld peaks at k=3 (88.80), PDDL at k=5 (80.40); DyLAN ALFWorld k=5 (88.80), PDDL k=3 (69.50); "larger k injects noise, smaller k misses context"; k=1 (74.80) vs k=5 (80.40) is a 5.60-point gap. Private rolling window K_max inverted-U: PDDL best K_max=5 (74.44), K_max=3 66.21, K_max=8 67.33; ALFWorld best K_max=6 (88.81). Collective EMA α inverted-U, best α=0.5 on both (PDDL 74.44, ALFWorld 88.81), α=0.3 → 67.80/81.34, α=0.8 → 65.89/84.33. / https://arxiv.org/abs/2609.15009 / 2026-10-20 / primary
- **Platform-level memory guidance from AgentScope (design guidance, no controlled experiment).** AgentScope separates agent memory modules from a "message hub" and offers agent-level fault handling via "the agent's ability in AgentScope (e.g., memory module and message hub) to critique for semantic error checking such as self-critique, pairwise critique, and human-augmented critique"; RAG agents may load a shared KnowledgeBank object OR a copy, and "a modification to an object may affect all the agents who use it" — i.e. shared vs private is a per-agent choice, and fusion weights are configurable because "knowledge may be of different importance or trustworthiness". / https://arxiv.org/abs/2402.14034 / 2026-10-20 / primary

### (d) Does "more agents" help?

- **YES, for independent sampling + voting, on hard tasks, with weaker models.** "More Agents Is All You Need" (Agent Forest = sample N times, majority vote): accuracy gains GSM8K 12%–24%, MATH 6%–10%, Chess 1%–4%, MMLU 5%–11%, HumanEval 4%–9%. With 15 samples Llama2-13B reaches 59% on GSM8K, beating Llama2-70B's 54%. Relative gain η (vs single query) is task- and model-difficulty-dependent: GSM8K (easy) Llama2-13B 69% / Llama2-70B 37% / GPT-3.5-Turbo 16%; MATH (hard) 200% / 120% / 34%. / https://arxiv.org/abs/2402.05120 / 2026-10-20 / primary
- **…but the gain is NON-monotone in difficulty, and depends on step count and answer prior.** Same paper, controlled synthetic task: Property 1 "Gains increase then decrease by rising the inherent difficulty" (best at I=100–200; at I=400 "gains taper off, implying that excessive complexity may exceed the model's reasoning capabilities"); Property 2.1 "Gains increase with the number of steps" (4%–18% at {I=10,K=2} vs 16%–48% at {I=100,K=4}); Property 3 "performance increases with the prior probability" (1/K of the answer space). / https://arxiv.org/abs/2402.05120 / 2026-10-20 / primary
- **…and it FAILS when agents must read each other.** Same paper: "two notable exceptions are observed when integrated with the debate method with the Llama2-13B and Llama2-70B models, which result in failed cases. This failure in performance is attributed primarily to the noise generated by referencing the answers of other agents during the debate process. The synthesized responses, which incorporate input from multiple agents, disrupt the coherence of the code logic, leading to the observed performance degradation." Also: Agent Forest standalone loses to the competition method on Chess for Llama2-13B/70B. / https://arxiv.org/abs/2402.05120 / 2026-10-20 / primary
- **NO, once the single agent is already good.** Google/MIT capability ceiling: "tasks where single-agent performance already exceeds 45% accuracy experience negative returns from additional agents, as coordination costs exceed diminishing improvement potential" (β=−0.236, p=0.004). Consistent with SWE-bench Verified showing −15% to −2% for ALL MAS architectures "consistent with high single-agent baselines (>>45%) for most models". / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **NO, on sequential / tool-heavy work.** Same paper: tool-coordination trade-off β=−0.096, p=0.002 — "tool-heavy tasks (e.g., 16-tool business workflows) suffer from multi-agent coordination overhead, with efficiency penalties compounding as environmental complexity increases"; Hybrid overhead 515% with success 0.21 on workbench (16 tools); Terminal-Bench (2 tools) Centralized degrades −19%. And all MAS degrade on PlanCraft −39% to −70%. / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **NO, past a model-specific optimum in agent count.** Same paper, n_a ∈ {1,3,5,7,9}: "Gemini-2.0 Flash exhibits a clear optimum at 7 agents before degradation, while Gemini-2.5 Pro's decentralized architecture peaks earlier despite its higher single-agent baseline. The centralized architecture demonstrates more stable scaling for Flash but shows diminishing returns for Pro beyond 5 agents… the optimal number of agents depends on both model capacity and coordination strategy, with coordination overhead eventually outweighing parallelization benefits." / https://arxiv.org/abs/2512.08296 / 2026-10-20 / primary
- **NO, when the protocol rather than the count is the variable.** MachineSoM: "merely increasing the number of agents or the number of collaboration rounds does not consistently yield better outcomes. The balance between agent quantity and strategies emerges as a key determinant in collaboration." / https://arxiv.org/abs/2310.02124 / 2026-10-20 / primary
- **Scaling is LOGISTIC, not monotone, and it saturates.** MacNet collaborative scaling law f(|V|) = γ/(1+e^{−β(log|V|−α)}) + δ, "a node magnitude of 2^4 appears to be a reasonable choice"; scaling from 2^0 to 2^6 (>1000 agents) "initially grows slowly… then leads to a rapid improvement before reaching a saturation point." / https://arxiv.org/abs/2406.07155 / 2026-10-20 / primary
- **Budget-aware compute beats fixed compute.** Adaptive Inference-Time Compute: a generative self-evaluation lets the model emit one token predicting whether a restart would be better; "74% of the improvement from using 16 samples can be achieved with only 1.2 samples on average", "50-75% of samples can be pruned early in generation with minimal degradation", AlpacaEval win rate vs GPT-4 21% → 34% with 16 samples, GSM8K 84% → 91%. / https://arxiv.org/abs/2410.02725 / 2026-10-20 / primary
- **Layered (multi-round) aggregation beats a single round, and beats a ranker.** MoA: 3 layers / 6 proposers 65.1% ±0.6 AlpacaEval 2.0 LC win rate vs GPT-4 Omni 57.5% (+7.6); 2 layers (MoA-Lite) 59.3% (+1.8). MT-Bench 9.25 ±0.10 vs GPT-4 Omni 9.19. MoA "significantly outperforms an LLM-ranker baseline", showing the aggregator "performs sophisticated aggregation over all proposed generations" rather than selecting one. Proposer count is monotone: n=1 47.8, n=2 58.8, n=3 58.0, n=6 61.3 (multi-proposer) vs 47.8 / 54.5 / 56.1 / 56.7 (single-proposer) — "using multiple different LLMs consistently yielded better results" at every n. / https://arxiv.org/abs/2406.04692 / 2026-10-20 / primary
- **Diverse agents beat identical agents, and identical agents are the classic failure.** MoA: "the collaborativeness phenomenon is widespread among LLMs… an LLM tends to generate better responses when presented with outputs from other models, even if these other models are less capable by itself" (Figure 1: every model's LC win rate improves when given other models' answers). GPTSwarm: with all IO agents prompted identically, "we observe no score improvement over the single agent baseline"; with 7 role-differentiated IO agents the optimized swarm improves by 2.1% ±1.1% over 5 training seeds. / https://arxiv.org/abs/2406.04692 , https://arxiv.org/abs/2402.16823 / 2026-10-20 / primary

### (e) Credit assignment

- **The one LLM-native credit-assignment mechanism is currently a STUB: identical credit to every action.** Agent Lightning's LightningRL decomposes a trajectory into per-call transitions (input, output, reward); the credit assignment module "allocates trajectory-level returns to responses generated by each call"; "In our current implementation, LightningRL simply assumes each action within the episode has the same value, equal to the final return R." The paper itself flags the gap: "The credit assignment module allows for future integration of more sophisticated strategies, such as assigning credit based on heuristics or learned models. One potential avenue for future work is introducing a high-level value function to estimate the expected return for each action a_t individually, providing a more nuanced credit distribution." Long-horizon credit assignment is listed under future work. / https://arxiv.org/abs/2508.03680 / 2026-10-20 / primary
- **Credit assignment in Agent Lightning is per-CALL, not per-ROLE, and it enables selective optimisation of one agent in a multi-agent system.** "Agent Lightning enables selectively optimizing agents within a multi-agent system, by including the corresponding agent's transitions in the optimization process. Compared to the masking approach, selecting transitions is much more convenient and intuitive." Sparse-reward relief comes from AIR (Automatic Intermediate Rewarding): "AIR enables the assignment of intermediate rewards to transitions based on system monitoring signals (such as tool call return statuses) … mitigating the sparse reward problem". For multi-LLM settings the paper is explicit that the simple route is suboptimal: "A more principled approach would use multi-agent reinforcement learning (MARL) or game theory, treating each LLM as an agent with its own objective and policy." / https://arxiv.org/abs/2508.03680 / 2026-10-20 / primary
- **DENSE per-turn credit beats sparse terminal credit for LLM agents.** "Reinforcing Multi-Turn Reasoning in LLM Agents via Fine-Grained Reward Structure and Credit Assignment": three reward granularities (terminal / delayed / per-turn) → three turn-level MDP formulations with GRPO and PPO variants each; "for both GRPO and PPO, dense per-turn reward structures consistently outperform sparse terminal and delayed reward structures in terms of training dynamics and numerical results"; PPO with dense per-turn rewards gives the highest answer correctness among all compared SOTA on search tasks. / https://arxiv.org/abs/2505.11821 / 2026-10-20 / primary
- **LLM-as-credit-critic works, and it beats hand-designed value decomposition — but the evidence is MARL, not LLM-MAS.** "Speaking the Language of Teamwork" (LLM generates dense agent-specific rewards from a natural-language task description and team goal; learned potential-based reward function over multiple queries to reduce ranking-error impact; faster convergence and higher policy returns than SOTA MARL baselines). / https://arxiv.org/abs/2502.03723 / 2026-10-20 / primary
- **Decomposing a shared reward into per-agent contributions via an LLM critic is demonstrated end-to-end.** LLM-MCA: "reformulate credit assignment to the two pattern recognition problems of sequence improvement and attribution… a centralized LLM reward-critic which numerically decomposes the environment reward based on the individualized contribution of each agent"; LLM-TACA extends it with explicit task assignment by passing an intermediary goal to each agent policy. "Both our methods far outperform the state-of-the-art on a variety of benchmarks, including Level-Based Foraging, Robotic Warehouse, and our new Spaceworld benchmark"; the released trajectory datasets carry per-agent reward annotations sampled from the LLM critic. Motivating observation: "humans manually inspecting agent behavior often generate better credit evaluations than existing methods." / https://arxiv.org/abs/2502.16863 / 2026-10-20 / primary
- **Attributing a failure to an agent in a natural-language swarm is measurably hard, and degrades with log length.** Who&When: best method 53.5% agent-level / 14.2% step-level; all-at-once step-level 12.50% is BELOW the 19.06% random baseline; all methods degrade with context length and "converge to near 0%" at maximum context; but at the STATISTICAL level the methods "still yield meaningful insights": the single most decisive agent predicted by all methods is consistent with ground truth (agent 3), and the top-2 are consistent in 2 of 3 cases. Human annotation is itself expensive and uncertain (30.9/30.2/23.2 human-hours; 15–30% uncertain). / https://arxiv.org/abs/2505.00212 / 2026-10-20 / primary
- **LLM judges are order-biased — any peer-ranking or credit mechanism built on an LLM judge must control for position.** "Large Language Models are not Fair Evaluators": "the quality ranking of candidate responses can be easily hacked by simply altering their order of appearance in the context… Vicuna-13B could beat ChatGPT on 66 over 80 tested queries with ChatGPT as an evaluator"; fixes = Multiple Evidence Calibration, Balanced Position Calibration (aggregate across orders), Human-in-the-Loop. / https://arxiv.org/abs/2305.17926 / 2026-10-20 / primary
- **The same bias shows up in multi-agent evaluation settings and is fixable by peer rank + peer discussion.** PRD: pairwise LLM evaluation suffers "self-enhancement (favoring its own answers) and positional bias"; Peer Rank aggregates every peer's pairwise preferences, Peer Discussion has two LLMs discuss toward agreement; both "achieve higher accuracy and align better with human judgments" on two benchmarks, and PR can induce a relatively accurate anonymous self-ranking of models. / https://arxiv.org/abs/2307.02762 / 2026-10-20 / primary

### Guidance / failure-mode evidence (bears on track (b) GUIDANCE)

- **System design, not model capability, is the first-order cause of MAS failure.** MAST: 1642 annotated traces from 7 frameworks; failure rates 41%–86.7% across 7 SOTA open-source MAS. 14 failure modes in 3 categories. FC1 (system design) — FM-1.3 step repetition 15.7%, FM-1.5 unaware of termination conditions 12.4%, FM-1.1 disobey task specification 11.8%, FM-1.4 loss of conversation history 2.80%, FM-1.2 disobey role specification 1.5%. FC2 (inter-agent misalignment) — FM-2.6 reasoning-action mismatch 13.2%, FM-2.3 task derailment 7.4%, FM-2.2 fail to ask for clarification 6.8%, FM-2.1 conversation reset 2.20%, FM-2.5 ignored other agent's input 1.90%, FM-2.4 information withholding 0.85%. FC3 (task verification) — premature termination, no/incomplete verification, incorrect verification. / https://arxiv.org/abs/2503.13657 / 2026-10-20 / primary
- **Better protocol beats better model, and better protocol beats more agents.** Same paper: with the same underlying model, workflow and prompt changes give "max improvements of 15.6%"; MetaGPT has 60–68% fewer FC1+FC2 failures than ChatDev but 1.56× more FC3 failures; GPT-4o shows 39% fewer FC1 failures than Claude 3.7 Sonnet in the same MetaGPT framework. LLM-annotator agreement κ=0.77 with humans, 0.79 out-of-domain (human IAA κ=0.88). / https://arxiv.org/abs/2503.13657 / 2026-10-20 / primary
- **Most frequent coordination failure is "didn't ask / didn't say", not "couldn't compute".** MAST FC2's two most common modes are reasoning-action mismatch (13.2%) and task derailment (7.4%), then failing to ask for clarification (6.8%) and ignoring other agents' input (1.9%) / information withholding (0.85%) — i.e. a minority of failures are communication breaks, but the paper notes "the errors we observe in FC2 occur even when agents within the same framework communicate using natural language. This signals a deeper agent interaction dynamic challenge: the collapse of 'theory of mind', where agents fail to accurately model other agents' informational needs." / https://arxiv.org/abs/2503.13657 / 2026-10-20 / primary
- **Coordination protocol must specify termination.** MAST's FM-1.5 "unaware of termination conditions" is 12.4% of failures, and FM-3.1 premature termination is the dominant mode for AppWorld, "potentially due to its star topology and lack of a predefined workflow making termination conditions less obvious". CAMEL's fix is an explicit end-of-task token: "This token is used once the user believes the task is done. This ensures that the chat is terminated when the user is satisfied. Without doing so, the agents might fall into a chatting loop." / https://arxiv.org/abs/2503.13657 , https://arxiv.org/abs/2303.17760 / 2026-10-20 / primary
- **Platform-level mechanical safety net.** AgentScope's fault-tolerance ladder: auto-retry with configurable max_retries; rule-based correction tools for cheap format fixes (unmatched braces, JSON extraction) at "no LLM API call cost"; customizable fault handlers (parse_func / fault_handler / max_retries); agent-level fault handling via memory module + message hub for "self-critique, pairwise critique, and human-augmented critique"; and a CHAT-level logging system. / https://arxiv.org/abs/2402.14034 / 2026-10-20 / primary

## Conflicting evidence

- **"Mesh/dense wins" vs "irregular beats regular" vs "centralized beats everything".** MacNet: dense mesh > tree > chain on average, and irregular > regular. AgentPrune: of the static spatial topologies, Complete Graph (83.15) > Random Graph (83.76? no — Random 83.76 is *higher*) > Layered 78.41 > Chain 82.35 > Tree 81.89 > Star 80.79 on MMLU. Google/MIT: Centralized (orchestrator bottleneck) is the strongest architecture on error containment (4.4× vs 17.2×) and the best on decomposable tasks (+80.8%), while Independent (no communication) is worst. Partial reconciliation: "Centralized" in Google/MIT = an orchestrator/verifier bottleneck, which is functionally the "convergent node" that MacNet warns about; MacNet's mesh is layered peer refinement with divergence preferred. So the recurring shape is: dense/peered for GENERATION, one convergent/validating node for AGGREGATION — not a single uniform topology.
- **"More agents helps" (MoA n-monotone; Agent Forest monotone) vs "more agents does not consistently help" (MachineSoM) vs "capability ceiling 45%" and "optimum at 5–7 agents" (Google/MIT) vs "K=10 teams worse than K=5" (LTS memory-free baseline).** Reconciliation: the monotone cases count INDEPENDENT samples that are then aggregated (voting, layered refinement). The non-monotone cases count agents that must interleave over one shared sequential state, or where the single agent is already >45% accurate, or where the protocol is unchanged while the count grows.
- **"Role composition doesn't matter" (MachineSoM: trait-defined societies indistinguishable, p>0.05 on all three datasets) vs "role selection matters enormously" (DyLAN: +10.1 pp overall over no optimisation, +25.0 pp on one subject; MoA: proposer/aggregator roles differ by up to 22.3 points).** Reconciliation: role LABEL/PERSONA is nearly irrelevant; measured CONTRIBUTION and the interaction PATTERN (who proposes vs who aggregates, who reviews vs who writes) is what pays. A plugin that only gives agents role names has captured the cheap half of the effect.
- **"Human prior selection" is a reasonable baseline in some setups (DyLAN: 66.7 vs 63.5 no-optimisation, +3.2) yet can be worse than random (High School Statistics, Clinical Knowledge, Public Relations).** Reconcilable: priors help when candidate expertise aligns with the task and hurt when it does not or when the prior cannot see tool augmentation ("Unit Tester" and "Syntax Checker" were never selected for code generation).
- **Memory: CoMem says private+shared > shared > private; DecentMem says private-per-agent > centralized-shared; LTS says shared-with-gating > shared-share-all.** Reconcilable: the shared store is fine when admission is gated and views are isolated; a FLAT shared store is actively harmful. CoMem and LTS both show that the harm comes from unvalidated writes, and CoMem's asymmetry (private layer is the stronger safeguard: −12.03 without collective vs −9.34 without private) matches DecentMem's finding that homogenization is the dominant failure mode.
- **MAST reports "+9.4%" for TWO different interventions** (improving agent role specifications; making the CEO the final say). Either coincidence or the same number reused; the paper does not disambiguate. Treat "role-spec improvement ≈ +9.4%" as one datapoint with a caveat, not two.
- **Error amplification is a headline metric in Google/MIT (17.2× vs 4.4×) but the paper then shows it is NOT statistically significant** as a predictor (β̂=0.014, p=0.658). Any report that cites "centralized contains errors to 4.4×" as the mechanism for centralized's win is over-reading the paper; the paper attributes the win to efficiency (E_c) and overhead (O%).
- **DyLAN's own ablation contradicts "dynamic is always better": removing agent team reformation costs accuracy, but removing early stopping costs only efficiency.** And DyLAN's team-optimisation stage needs a preliminary trial (a warm-up cost) that the plugin has no analogue for.

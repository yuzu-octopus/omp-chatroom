# F15 — GUIDANCE and RETRIEVAL

## Angle

Question: should omp agents read coordination papers at runtime, or should the protocol be distilled
into a shipped playbook/skill? Sub-angles: (a) guidance artifacts as coordination protocol
(AGENTS.md / CLAUDE.md / Agent Skills / Cursor rules, with measured effect); (b) protocol-as-code
(MCP spec, GitHub Agentic Workflows, playbook/runbook repos); (c) does runtime retrieval of prior art
help (RAG-for-policies, tool-doc retrieval, long-context vs retrieval, context rot, agent memory);
(d) evidence AGAINST a coordination-literature retrieval tool; (e) what tool-research literature says
about a "search the literature" tool.

Bottom line from evidence: **distill, don't retrieve.** No primary source supports a
retrieval-over-coordination-literature tool. Every primary source that measures a *shipped, focused,
on-demand* protocol artifact (Skill, playbook, verified protocol, compiled system prompt) shows a
positive or at least process-positive effect; every primary source that measures *always-on, verbose,
or retrieved* context shows cost rises, correctness nulls, or distractor-induced failures.

## Claims

### (a) Guidance artifacts as coordination protocol

- AGENTS.md is deliberately minimal: plain Markdown, **no required fields**, "closest AGENTS.md to the
  edited file wins"; used by 60k+ OSS projects; stewarded by the **Agentic AI Foundation under the
  Linux Foundation** (OpenAI donated it, 9 Dec 2025; co-founded with Anthropic, Block, backed by Google,
  Microsoft, AWS, Bloomberg, Cloudflare). https://agents.md/ , https://github.com/agentsmd/agents.md ,
  https://openai.com/index/agentic-ai-foundation/ — 2026-10-20 — **primary**
- CLAUDE.md is **context, not enforcement**: "The more specific and concise your instructions, the more
  consistently Claude follows them"; target **<200 lines**; Claude Code also reads a repo's AGENTS.md;
  auto-memory is Claude-written, per-repo, capped at **first 200 lines or 25 KB**; subagents can keep
  their own auto memory. https://code.claude.com/docs/en/memory — 2026-10-20 — **primary**
- Cursor rules: 4 kinds (Project/User/Team/AGENTS.md), `.cursor/rules/*.mdc` with
  `description`/`globs`/`alwaysApply`; "Keep rules under 500 lines"; explicit anti-patterns —
  "Copying entire style guides: **Agent already knows common style conventions**";
  "Duplicating what's already in your codebase"; "Reference files instead of copying their contents."
  https://cursor.com/docs/rules — 2026-10-20 — **primary**
- Agent Skills is now an **open cross-platform standard** (Anthropic published it as such 18 Dec 2025;
  `agentskills.io` spec; `skills-ref` validator; ~30+ client implementations incl. Claude Code, Cursor,
  Gemini CLI, OpenCode, Goose, OpenHands, Letta, pi). Progressive disclosure is the core mechanism:
  L1 metadata ~100 tokens/skill (always), L2 SKILL.md body <5k tokens (on trigger), L3 bundled
  resources (zero cost until read); spec says keep SKILL.md <500 lines.
  https://agentskills.io/specification.md , https://agentskills.io/ , https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview ,
  https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills — 2026-10-20 — **primary**
- agentskills.io authoring guidance, directly on point for a coordination playbook:
  "**Overly comprehensive skills can hurt more than they help** — the agent struggles to extract what's
  relevant"; "Concise, stepwise guidance with a working example tends to outperform exhaustive
  documentation"; "**Add what the agent lacks, omit what it knows**"; "**Favor procedures over
  declarations**"; "**Provide defaults, not menus**"; "**Reasoning-based instructions work better than
  rigid directives**"; "The highest-value content in many skills is a list of **gotchas**";
  "Ask yourself: would the agent get this wrong without this instruction? If not, cut it."
  https://agentskills.io/skill-creation/best-practices.md — 2026-10-20 — **primary**
- **MEASURED FOR (Skills)**: SkillsBench — curated Skills raise avg pass rate **33.9% → 50.5%
  (+16.6 pp)** over 18 model-harness configurations on 87 tasks / 8 domains; per-config gains
  +4.1…+25.7 pp; "**Focused Skills with at most three modules outperform larger or exhaustive
  bundles**"; "smaller models with Skills can match larger models without them."
  https://arxiv.org/abs/2602.12670 (v4, 14 Jun 2026) — 2026-10-20 — **primary**
- SkillsBench v2 adds: 86 tasks / 11 domains / 7 configs / 7,308 trajectories; +16.2 pp avg, range
  +4.5 pp (Software Engineering) to +51.9 pp (Healthcare); **16 of 84 tasks negative**;
  "**Self-generated Skills provide no benefit on average**, showing that models cannot reliably author
  the procedural knowledge they benefit from consuming" (i.e. a *curated* playbook, not a
  model-authored one). https://arxiv.org/abs/2602.12670v2 — 2026-10-20 — **primary**
- **MEASURED AGAINST (context files)**: Gloaguen et al. (ETH Zürich + LogicStar), "Evaluating
  AGENTS.md", v3 29 Sep 2026 — context files **do not generally improve task success** and **increase
  inference cost by >20% on average**, across LLMs, agents, and both LLM-generated and
  developer-committed files. Behavioural split: "instructions in the context files are **well
  followed** by coding agents, **repository overviews … are not helpful**". Conclusion: "unnecessary
  requirements from context files make tasks harder, and human-written context files should describe
  **only minimal requirements**." Numbers from the paper body: LLM-generated files **−3%** avg success,
  developer-provided **+4%** avg; **+20% (SWE-bench Lite) / +23% (AGENTBENCH) cost**; steps +2.45 / +3.92.
  https://arxiv.org/abs/2602.11988 , PDF https://arxiv.org/pdf/2602.11988v1 — 2026-10-20 — **primary**
- **MEASURED (2-agent ablation, real repos)**: Khatri, "Do Context Files Help Coding Agents?" —
  17 real tasks, 3 repos, 288 gold-test-evaluated runs, Claude Code + Codex, three injection strategies
  (`none` / `always_on` full file / `selective` retrieval-style split). Correctness **null** (TOST
  bounded ≤10–15 pp; within-task omnibus p=1.000). Process effect **positive**: on OpShin, blind
  full-test-suite runs **3.67 → 2.44 → 1.67** across none/always_on/selective, ~**24%** wall-clock cut,
  because AGENTS.md warned the suite was slow. Verbatim: "the gain stems from **process, not
  pass-rate**"; "context can narrowly depress correctness but **never manufactured a pass**."
  https://arxiv.org/abs/2607.27250 , data https://github.com/codeprakhar25/context-files-coding-agents
  (key_numbers.md) — 2026-10-20 — **primary**
- **MEASURED (efficiency only)**: Lulla et al., ICSE JAWs 2026 — 10 repos, 124 PRs, Codex gpt-5.2-codex,
  paired with/without AGENTS.md: median wall-clock **−28.64%**, mean output tokens **−20.08%**,
  median output tokens **−16.58%**, "comparable task completion behavior" (correctness NOT evaluated).
  https://arxiv.org/abs/2601.20404 , PDF https://assets.empirical-software.engineering/pdf/jaws26-agents.md-efficiency.pdf — 2026-10-20 — **primary**
- **MEASURED (structure does not matter)**: McMillan, factorial study of 4 config-file structure
  variables over **1,650 Claude Code sessions / 16,050 function-level observations**, 3 models, 5 tasks:
  **none** of size / position / architecture / adjacent-conflict produced a detectable contrast after
  multiple-testing correction (affirmative-null BF10 0.05–0.10 for size & conflict). Only a
  within-session effect: each additional generated function ≈ **5.6% lower odds of compliance**
  (OR 0.944). https://arxiv.org/abs/2605.10039 — 2026-10-20 — **primary**
- **Corpus characterisation**: "Agent READMEs" — **2,303 context files across 1,925 repos**; developers
  prioritise functional context: test procedures **75.9%**, implementation details **70.8%**,
  architecture **68.1%**; non-functional (security **14.8%**, performance **14.5%**) rarely specified;
  files "evolve like configuration code through frequent, small additions."
  https://arxiv.org/abs/2511.12884 — 2026-10-20 — **primary**
- **Governance of the guidance layer should be deterministic, not LLM-orchestrated**: "A Deterministic
  Control Plane for LLM Coding Agents" over 10,008 repos / 6,145 agent config files: **10.1%** of tracked
  paths are SHA-256 exact duplicates across independent repos (75.5% of clone pairs cross org
  boundaries); **58%** single-commit; **<1%** declare permission boundaries (vs 33% of Actions
  workflows). https://arxiv.org/abs/2606.26924 — 2026-10-20 — **primary**
- Anthropic's own first-party multi-agent engineering write-up: the working artifact is not a rules
  dump but "**frameworks for collaboration that define the division of labor, problem-solving
  approaches, and effort budgets**"; they "instilled **good heuristics rather than rigid rules**";
  failures they had to fix by prompting were "spawning 50 subagents for simple queries, scouring the
  web endlessly for nonexistent sources, and distracting each other with excessive updates"; they
  "**taught the orchestrator how to delegate**" and "scale[d] effort to query complexity".
  https://www.anthropic.com/engineering/multi-agent-research-system — 2026-10-20 — **primary**
  (vendor source for Anthropic's own system).

### (b) Protocol-as-code

- MCP is the tool-integration standard and has a **first-class natural-language guidance channel**: the
  server MAY return `instructions` in the `InitializeResult` ("Optional instructions for the client").
  MCP architecture principles include "**Servers should not be able to read the whole conversation,
  nor 'see into' other servers**" and capability negotiation; resources are **application-driven**
  (the client decides how to include them; the spec explicitly lists "implement automatic context
  inclusion, based on heuristics or the AI model's selection"); prompts are **user-controlled** and
  intended to be exposed as slash commands.
  https://modelcontextprotocol.io/specification/2025-11-25/architecture ,
  /basic/lifecycle , /server/resources , /server/prompts — 2026-10-20 — **primary**
- GitHub Agentic Workflows (`gh-aw`) = protocol-as-code with a **two-layer split**: YAML frontmatter
  (triggers, permissions, tools, `safe-outputs`) + Markdown body (the agent's instructions);
  `gh aw compile` → hardened `.lock.yml`. Read-only by default; writes only through validated
  safe-outputs jobs. Docs' own one-liner: "**Markdown defines the task; frontmatter defines the
  workflow's capabilities and boundaries; safe outputs define which GitHub writes are allowed.**"
  https://github.com/github/gh-aw (README) , https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-github-agentic-workflows — 2026-10-20 — **primary**
- gh-aw ships an **agent-facing prompt corpus + index** (not a corpus the agent must search blindly):
  `llms.txt` indexes ~90 prompt docs; README says "For AI agents and retrieval tools, use the published
  agent prompt index, full prompt corpus, and AI-readable project summary." Its `patterns.md` is a
  **pattern router** that matches the request to one named playbook and loads only that doc.
  https://github.github.com/gh-aw/llms.txt , https://raw.githubusercontent.com/github/gh-aw/main/.github/aw/patterns.md — 2026-10-20 — **primary**
- **First-party statement that a shipped protocol is a DISTILLED artifact and that runtime retrieval
  scope must be constrained**: gh-aw's `multi-agent-research.md` is described as "**Distilled from the
  OpenAI Cycle Double Cover (CDC) prompt**", and its "Information Retrieval Scope" section says
  "**Web search and external retrieval may be used only for background material and named standard
  results. Do not search for a solution to this exact task.**" It also encodes the coordination
  patterns a shared room would need: anti-convergence (information hiding, idea-keyed registry,
  delayed cross-pollination), blocked-route bookkeeping with reopen conditions, domain-specific
  adversarial auditor checklist ("Generic 'check carefully' instructions fail"), and an
  **artifact-only return contract** ("Return only when a verified solution survives adversarial audit …
  Never return: a partial result, reduction, … or explanation of why the task is hard").
  https://raw.githubusercontent.com/github/gh-aw/main/.github/aw/multi-agent-research.md — 2026-10-20 — **primary**
- gh-aw also ships the **mechanics** of a work queue as protocol, not guidance: `tools.work-queue`
  schedules **immutable DAGs and Claim-scoped effects**; "Predecessors consume no Claims; **successors
  wait for predecessor Results**"; fair scheduling, bounded dispatch, `work_queue_claim_finish` with
  `outcome: completed|cancelled`, and a "Load details only when needed" section for operator docs.
  https://raw.githubusercontent.com/github/gh-aw/main/.github/aw/work-queue.md — 2026-10-20 — **primary**
- llms.txt v2 (the origin author's own spec): the index-and-fetch pattern — "**The file itself stays
  small enough to fit in context. The detail lives behind the links, and is fetched only when
  needed.**"; "Agents are expected to view or search `llms.txt` to find the information they need, then
  follow the relevant links"; a sitemap is "not a substitute" because it "will generally cover documents
  that in aggregate will be too large to fit in an LLM context window". https://llmstxt.org/ — 2026-10-20 — **primary**
- **Strongest primary support for "distilled protocol + runtime enforcement beats prompt-only"**:
  TraceFix — an agent synthesises a protocol topology as an IR, generates PlusCal, repairs it with
  TLA+ counterexamples, then **compiles the verified process bodies into per-agent system prompts** and
  runs a **runtime monitor that rejects out-of-topology coordination operations**. 48 tasks / 16
  scenario families: 100% reach TLC verification, **62.5% first-attempt**, ≤4 repair iterations,
  verification <60 s. 3,456-run comparison: topology-monitored **89.4%** avg task completion (81.5%
  full); under reduced model capability, verified protocols **degrade at roughly half the rate** of
  prompt-only and chat-only baselines. Paired fixed-runtime ablation: **deadlock/livelock 31.1% → 14.1%**.
  https://arxiv.org/abs/2605.07935 — 2026-10-20 — **primary**
- `tap` — file-based protocol for **heterogeneous** Claude + Codex collaboration with no shared runtime:
  file-first message preservation (Tier 1) + real-time notification (Tier 2) + git worktree isolation;
  27-day / 37-generation self-application, 209 PRs, 717 artifacts; of 375 review artifacts
  **69.8%** of heterogeneous-model reviews recorded ≥1 defect vs **53.1%** homogeneous.
  https://arxiv.org/abs/2606.14445 — 2026-10-20 — **primary**
- Claude Code **agent teams** (first-party, shipped): shared task list with **dependencies** — "a pending
  task with unresolved dependencies **cannot be claimed** until those dependencies are completed";
  claim via **file locking** to prevent races; `TeammateIdle`/`TaskCreated`/`TaskCompleted` hooks can
  **reject and send feedback** (exit 2) — a runtime gate on agent behaviour; "Agent teams add
  coordination overhead and use significantly more tokens than a single session"; subagent
  `description` fields above **15,000 tokens** trigger a startup warning, with detail pushed into
  each subagent's system prompt. https://code.claude.com/docs/en/agent-teams , https://code.claude.com/docs/en/sub-agents — 2026-10-20 — **primary**
- Letta: four-tier memory — **core memory blocks** (always in context), **archival memory** (search on
  demand), **recall** (past messages), **skills**; and notably "agents can write skills into their own
  memory systems, so that skills persist with the agent as part of its identity" (agent-scoped skills
  live in the agent's git-backed MemFS). https://docs.letta.com/configuration/skills — 2026-10-20 — **primary**
- Anthropic's memory-tool + context-editing release: on an internal agentic-search eval, **memory tool +
  context editing = +39%** over baseline, context editing alone **+29%**; in a 100-turn web-search eval,
  context editing let agents complete workflows that would otherwise fail **and cut token consumption
  by 84%**. https://www.anthropic.com/news/context-management — 2026-10-20 — **primary**

### (c) Does runtime retrieval of prior art help?

- **FOR, but only for content-QA in a large corpus**: OpenScholar — retrieval over **45M** open-access
  papers / **236M** passage embeddings; ScholarQABench (2,967 expert queries, 208 long-form answers);
  OpenScholar-8B beats GPT-4o by **5%** and PaperQA2 by **7%** on correctness; "**GPT4o hallucinates
  citations 78 to 90% of the time**, OpenScholar achieves citation accuracy on par with human
  experts"; wrapping GPT-4o with OpenScholar's datastore+retriever+self-feedback loop gives
  **+12%** correctness; experts preferred OpenScholar answers over expert-written ones **51%**
  (8B) and **70%** (GPT4o) of the time vs GPT4o's 32%. https://arxiv.org/abs/2411.14199 — 2026-10-20 — **primary**
  (Nature version https://doi.org/10.1038/s41586-025-10072-4)
- **FOR**: PaperQA2 — "matches or exceeds subject matter expert performance on three realistic
  literature research tasks"; writes Wikipedia-style summaries "significantly more accurate than
  existing, human-written Wikipedia articles"; **2.34 ± 1.99** contradictions per paper with **70%**
  human-validated. https://arxiv.org/abs/2409.13740 — 2026-10-20 — **primary**
- **FOR, in the same shape as a shipped playbook**: Agent Workflow Memory (AWM) — induce reusable
  **workflows from past experience** and *selectively* provide them: **+24.6%** (Mind2Web) and
  **+51.1%** (WebArena) relative success rate, fewer steps; online variant generalizes across
  task/website/domain gaps by **+8.9…+14.0** absolute points. https://arxiv.org/abs/2409.07429 — 2026-10-20 — **primary**
- **FOR, accumulate-and-distill**: ACE (Agentic Context Engineering) — treat context as an **evolving
  playbook** accumulated/refined/organised by Generator→Reflector→Curator, avoiding *brevity bias* and
  *context collapse*: **+10.6%** on agent benchmarks, **+8.6%** on finance, lower adaptation latency
  and rollout cost, works **without labelled supervision** from natural execution feedback, matches the
  top-ranked production agent on AppWorld's overall average. https://arxiv.org/abs/2510.04618 — 2026-10-20 — **primary**
- **FOR, memory-as-guidance**: MemGPT (virtual context management, OS-style memory tiers)
  https://arxiv.org/abs/2310.08560 ; Reflexion (verbal lessons in an episodic memory buffer, 91%
  pass@1 HumanEval) https://arxiv.org/abs/2303.11366 ; Voyager (growing library of executable skills)
  https://arxiv.org/abs/2305.16291 — 2026-10-20 — **primary**
- **Long-context is NOT a substitute**: RULER — 17 long-context LMs, 13 tasks; "almost all models
  exhibit large performance drops as the context length increases"; only **half** maintain
  satisfactory performance at 32K. https://arxiv.org/abs/2404.06654 — 2026-10-20 — **primary**
- NoLiMa — 13 models claiming ≥128K; at 32K **11 of 13 fall below 50%** of their short-context
  baseline; GPT-4o **99.3% → 69.7%**. https://arxiv.org/abs/2502.05167 — 2026-10-20 — **primary**
- Lost in the Middle — relevant info is used better near the beginning/end than in the middle.
  https://arxiv.org/abs/2307.03172 — 2026-10-20 — **primary**
- LongMemEval — commercial chat assistants and long-context LLMs show a **30% accuracy drop** on
  memory across sustained interactions; the useful decomposition is indexing → retrieval → reading.
  https://arxiv.org/abs/2410.10813 — 2026-10-20 — **primary**

### (d) Evidence AGAINST a coordination-literature retrieval tool

- **Decisive first-party guidance**: Anthropic, "Effective context engineering for AI agents" —
  explicitly prescribes a **hybrid**: "**CLAUDE.md files are naively dropped into context up front,
  while primitives like glob and grep allow it to navigate its environment and retrieve files
  just-in-time**"; "the guiding principle remains the same: **find the smallest possible set of
  high-signal tokens**"; cites **context rot**; warns "**runtime exploration is slower than retrieving
  pre-computed data**" and "**Without proper guidance, an agent can waste context by misusing tools,
  chasing dead-ends, or failing to identify key information**"; subagents should return **condensed
  1,000–2,000-token summaries**; compaction + structured note-taking + sub-agent architectures are the
  three long-horizon levers. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents — 2026-10-20 — **primary**
- **Context rot (originating report)**: Chroma evaluated **18 LLMs** (GPT-4.1, Claude 4, Gemini 2.5,
  Qwen3) and found "model performance grows increasingly unreliable as input length grows"; NIAH
  overestimates capability; **distractor impact amplifies as input length grows**; lower
  needle-question similarity degrades faster. https://www.trychroma.com/research/context-rot , code
  https://github.com/chroma-core/context-rot — 2026-10-20 — **primary**
- **Retrieval actively breaks agents**: NoisyBench / "Lost in the Noise" — across 11 datasets,
  contextual distractors cause **performance drops of up to 80%**; "**agentic workflows often amplify
  these errors by over-trusting noisy tool outputs**, and distractors can trigger emergent
  misalignment even without adversarial intent"; "**prompting, context engineering, SFT, and
  outcome-reward only RL fail to ensure robustness**"; and an **inverse scaling** trend — *more*
  test-time computation → *worse* performance in noisy settings — with attention visualisations
  showing disproportionate focus on distractor tokens. https://arxiv.org/abs/2601.07226 — 2026-10-20 — **primary**
- **Interference in multi-turn search agents specifically**: "Mitigating Context Interference" —
  "interference **primarily arises from the latest retrieved documents**"; a distill-based refiner
  mitigates it. https://arxiv.org/abs/2608.10743 — 2026-10-20 — **primary**
- **Retrieval is not free / can be harmful**: budget-aware Active RAG evaluation — "**retrieval harm is
  non-negligible**"; router rankings change across datasets and budgets; "simple uncertainty or
  retrieval-score baselines often **rival learned utility routers**"; recommends reporting frontiers,
  realised usage, **harm rates** and cost decompositions alongside accuracy.
  https://arxiv.org/abs/2607.24010 — 2026-10-20 — **primary**
- "Is Agentic RAG worth it?" — Enhanced vs Agentic RAG compared on performance **and cost**; the
  framing is a trade-off, not a blanket win. https://arxiv.org/abs/2601.07711 — 2026-10-20 — **primary**
- **Irrelevant retrieved docs hurt**: "The Power of Noise" — the retriever's top-scoring *non-relevant*
  docs "negatively impact the effectiveness of the LLM"; (the same paper's claim that random docs help
  by up to 35% is contested — see Conflicts). https://arxiv.org/abs/2401.14887 — 2026-10-20 — **primary**
- **A "search the literature" tool is a tool-retrieval problem with a huge corpus — and IR models are
  bad at it**: ToolRet — 7.6k retrieval tasks over **43k tools**; "even the models with strong
  performance in conventional IR benchmarks, exhibit **poor** performance on ToolRet. **This low
  retrieval quality degrades the task pass rate of tool-use LLMs.**" https://arxiv.org/abs/2503.01763 — 2026-10-20 — **primary**
- **Tool surface size is a cost and a distractor**: "How Many Tools Should an LLM Agent See?" —
  adaptive shortlist improves tool selection to **93.1% vs 87.1%** (Claude Sonnet 4.6) vs always
  showing 5; widening to **76.8% vs 60.9%** on medium-difficulty queries; ~200 tokens per tool
  description means 100 tools ≈ 20,000 prompt tokens. https://arxiv.org/abs/2605.24660 — 2026-10-20 — **primary**
- Toollery — "As LLM agents are exposed to hundreds to tens of thousands of skills, tools, and API
  functions, **full-library prompting becomes costly, slow, and less reliable**: each added candidate
  increases prompt tokens and latency, while longer candidate lists introduce more distractors."
  https://arxiv.org/abs/2609.22218 — 2026-10-20 — **primary**
- **Tool descriptions degrade behaviour when sloppy** (relevant to any new retrieval tool we add):
  Anthropic's tool-writing post — "**More tools don't always lead to better outcomes**"; bloated
  tool sets create "ambiguous decision points about which tool to use"; Claude Code caps tool
  responses at 25,000 tokens; when Claude's web-search tool kept appending "2025" to queries, that
  **biased results and degraded performance** until the tool *description* was changed; a tool-testing
  agent that rewrote a description cut future agents' task completion time by **40%**.
  https://www.anthropic.com/engineering/writing-tools-for-agents — 2026-10-20 — **primary**
- Anthropic, "Building effective agents" — "the most successful implementations use simple, composable
  patterns rather than complex frameworks"; "**add complexity only when it demonstrably improves
  outcomes**"; clear tool documentation and testing is a core principle.
  https://www.anthropic.com/research/building-effective-agents — 2026-10-20 — **primary**
- **Long instructions have an instruction-following ceiling** (bears on how big a shipped playbook may
  be): AGENTIF — 707 human-annotated instructions from 50 real agentic apps, averaging **1,723 words**
  (max 15,630) and **11.9 constraints**; "current models **generally perform poorly**, especially in
  handling complex constraint structures and tool specifications." https://arxiv.org/abs/2505.16944 — 2026-10-20 — **primary**
- SOP-Bench — 2,000+ tasks from human expert-authored industrial SOPs; ReAct success averages **48%**
  (function-calling 27%); best per-domain 57%–100%; newer models are not automatically better
  (Claude 4 Opus 72.4% vs Claude 4.5 Sonnet 63.3%). https://arxiv.org/abs/2506.08119 — 2026-10-20 — **primary**
- **The nearest thing to "agents coordinate at runtime"**: Runtime Agent Coordination (RAC) — selects
  agents at runtime, assigns scoped work contracts, adds artifact-grounded verification. Runtime
  *selection* gave the best mean per host, but **adding contracts and verification reduced those
  means** — "exposing the limits of additional coordination mechanisms under constrained budgets."
  (Not a literature-reading experiment, and it is the wrong shape: runtime *selection*, not runtime
  *learning from papers*.) https://arxiv.org/abs/2610.00980 — 2026-10-20 — **primary**
- **The measurement bar any new coordination mechanism must clear**: "How Much Coordination Gain Is
  Real?" — configuration-equivalent protocols differ by **+10 pp and 0 pp** across two n=100 seeds;
  pooled **+5 pp, Wilson CI [−2,+12]**, not significant; largest single-seed contrast **+18 pp
  (p_corr=0.012) did not reproduce** (−3 pp, p_corr=1.0) at the second seed; **7 of 10** recent
  multi-agent coordination architectures report headline effects **below** this local floor; proposes
  **coordination-active pass^k** as the minimum reporting protocol.
  https://arxiv.org/abs/2606.20695 , project page https://abekek.github.io/coordination-noise-floor-protocol/ — 2026-10-20 — **primary**
- **Coordination gain needs *visibility*, and visibility is cheap**: PASC (ESEM 2026, peer-reviewed) —
  two homogeneous agents in a shared Git tree, each observation prepended with a structured
  **peer-activity block** (commits, lifecycle transitions, test/error output). Significant lift over
  single-agent on the full Python subset of SWE-Bench Pro with two independently-developed LLMs; the
  **"silent" two-agent baseline is statistically equivalent to the single-agent one**, so the gain is
  from coordination, not parallelism; vs silent baseline, **−20% cost per resolved task** and **−47%
  destructive concurrent edits**; "beyond two agents, active interference increases several-fold".
  https://doi.org/10.4230/LIPIcs.ESEM.2026.18 — 2026-10-20 — **primary**

## Conflicting evidence

1. **SkillsBench (+16.6 pp) vs "Evaluating AGENTS.md" (no success gain, +20% cost).** Both primary,
   both peer-track, opposite signs. Reconcilable read: the discriminator is **artifact discipline**, not
   artifact type. Skills are *on-demand, focused (≤3 modules), procedural, trigger-described*;
   AGENTS.md-class files are *always-on and often overviews* — and the AGENTS.md paper itself says
   instructions are followed but **overviews are not helpful**, and that files should describe "only
   minimal requirements". A shipped Skill is the disciplined form; an always-on protocol dump is the
   undisciplined form. → supports a *Skill-shaped* playbook, not a big always-on protocol and not a
   retrieval tool.
2. **AGENTS.md efficiency gains (JAWS −28.64% runtime, −16.58% output tokens) vs AGENTS.md correctness
   nulls (Khatri, McMillan).** Reconcilable: guidance reliably changes *process and cost*; whether it
   changes *outcome* depends on the task's bottleneck. Khatri's failure triage says agents fail on
   **implementation skill, not missing repository knowledge** — i.e. guidance can only help where the
   missing knowledge is guidance-shaped (build commands, "the suite is slow", non-standard conventions),
   never where the gap is craft.
3. **"The Power of Noise" (2401.14887) claims random docs improve LLM accuracy by up to 35%** — but
   the same paper's other finding (top non-relevant docs *hurt*) and the 2026 replication
   (2607.03615) show the "power of noise" pattern "**can appear, weaken, or disappear under small
   changes to prompt formulation and decoding limits**" and "cannot be robustly confirmed as a general
   benefit of noisy retrieval". Do not cite the 35% as established.
4. **Anthropic says runtime exploration is useful** ("just in time" strategies, progressive
   disclosure, hybrid CLAUDE.md + glob/grep) **and** that it "is slower than retrieving pre-computed
   data" and needs guidance to avoid dead-ends. Both are true: the sanctioned pattern is *just-in-time
   retrieval of a specific, known artifact* (a file, a tool definition, a reference section), never
   *open-ended search over a literature corpus* to discover a protocol.
5. **TraceFix shows compiled, verified protocols + a runtime monitor beat prompt-only** (DL/LL
   31.1%→14.1%) — while **RAC shows adding contracts+verification to a working system reduced the
   means**. Reconcilable: mechanisms help when the baseline *lacks* coordination, and hurt when
   coordination overhead is added to a host that already had an effective structure. Also note
   TraceFix's "runtime monitor that rejects out-of-topology operations" is a *mechanics* component
   (F14's territory) attached to a *guidance* component — the primary evidence does not support
   guidance alone.
6. **The noise floor (2606.20695)** may swallow any small measured gain in a coordination mechanism:
   7 of 10 recent coordination architectures report effects below it, and the largest single-seed
   effect (+18 pp) reversed at a second seed. Any claim our plugin's guidance/mechanics "improves"
   coordination must be measured with a **paired, coordination-active** protocol (pass^k restricted to
   trials where the mechanism is logically active), and needs a detectable effect of roughly
   **≥15–20 pp** on the same model/benchmark to be distinguishable from noise. This raises the bar for
   shipping *any* new mechanism, guidance or retrieval.
7. **Shared files as coordination channel vs as overhead** (2608.16801): shared files cut output
   tokens ~42% at 8 agents on message-heavy work but *add* overhead where files already carry the
   coordination. Directly relevant to a room that already ships a room log + a skill: a second
   artifact channel (e.g. a searchable literature corpus) may be pure overhead unless it replaces
   messaging.
8. **"Naming one agent coordinator creates no communication hub and gives no reliable improvement"**
   (2608.16801) vs Anthropic's orchestrator-worker pattern being the highest-leverage multi-agent
   design (90.2% over single-agent on their internal eval, token usage explaining 80% of BrowseComp
   variance). Reconcilable: a *named* role without a *protocol* (task list, claims, dependencies) is
   cosmetic; the orchestrator pattern works because of what surrounds it.

## Gaps

- **No primary study ablates "shipped coordination playbook" vs "no playbook" inside a shared room**,
  with a noise-floor-corrected, coordination-active protocol. Closest analogues measure generic
  context files (2602.11988, 2607.27250), Skills in non-coordination domains (2602.12670), or
  system-level protocol+monitoring (2605.07935). Nothing measures a coordination playbook.
- **No primary evidence whatsoever on agents reading *coordination* literature at runtime.** The
  literature-search-tool evidence (OpenScholar, PaperQA2, STORM, AI Scientist, AutoResearchBench) is
  all about answering *content* questions in a domain corpus, not about an agent learning how to
  coordinate. AutoResearchBench is the closest cautionary datapoint: frontier LLMs that have largely
  conquered general web-browsing benchmarks score only **9.39%** on Deep Research and **9.31% IoU**
  on Wide Research (https://arxiv.org/abs/2604.25256) — deep literature discovery by agents is
  *hard*, and the failure mode (missing the right paper) maps directly onto "agent fails to find the
  coordination rule that applies".
- **Independent eval of AI Scientist** (https://arxiv.org/abs/2502.14297) is the closest evidence
  that an agent with a literature-search tool produces *bad* meta-judgements: its literature reviews
  "produced **poor novelty assessments**, often misclassifying established concepts … as novel";
  42% of experiments failed from coding errors; some papers contained hallucinated numbers. Direct
  caution: do not let omp agents adjudicate coordination novelty from retrieved papers.
- **Anthropic publishes no first-party accuracy number for Skills** (the Skills research page gives no
  percentage; SkillsBench is third-party). Treat +16.6 pp as third-party benchmark evidence.
- **gh-aw's work-queue spec** (DAG semantics, fair-scheduling algorithm, Claim lifecycle) was read only
  at the agent-instructions level, not at the specification level
  (`docs/src/content/docs/specs/work-queue-specification.md` not fetched) — that spec is the most
  promising primary template for the *mechanics* track and should be read by the mechanics worker.
- **Not verified in this session**: whether the omp host actually loads `skills/` shipped inside a
  *plugin* package (as opposed to `~/.omp/agent/skills/`), and whether `plugin/package.json` "files"
  including "skills" is sufficient for the packaged route. The installed host has an
  agent-plugin-format skill validator and a `Skill.containRoot` containment rule, which suggests yes,
  but this was not executed (plugin is read-only for this task).
- **No measurement of our own plugin's guidance artifacts.** The reported 75.0–85.7% unprompted
  room-discovery rate measures *discovery*, not *coordination quality*; nothing in the evidence base
  lets us claim the shipped `routing-rule.md` + `SKILL.md` improves swarm outcomes. Per
  2606.20695, such a claim needs a paired, coordination-active protocol with a ≥15–20 pp detectable
  effect — a meaningful amount of new measurement work before any guidance/mechanics change can be
  justified on evidence.

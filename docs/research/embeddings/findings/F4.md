# F4 — Multilingual / MMTEB embedding models

## Angle

MMTEB scores, sizes, dims, licences, context, CPU latency, and English-vs-multilingual
tradeoff for local (CPU-capable, text-only) multilingual embedding models.

**Method note (important).** Two classes of number appear below:

- **`[parquet-recompute]`** — my own aggregation over the official MTEB results
  dataset `mteb/results` (HuggingFace, parquet, 4 shards, `train` split; dataset
  `lastModified` 2026-10-04, fetched 2026-10-07). Task membership resolved by
  importing `mteb` (v2.x) `get_benchmark("MTEB(Multilingual, v2)")` = 131 tasks and
  `get_benchmark("MTEB(eng, v2)")` = 41 tasks, then `avg(score)` per (model, task),
  then mean over tasks. **Coverage count (matched tasks / benchmark size) is printed
  with every such number** — incomplete coverage means the number is NOT a
  leaderboard-equivalent score.
- **Published** — model card / paper / official leaderboard value with its own date.

`[parquet-recompute]` uses per-task means over all available language subsets, so it
is "mean(task)", not Borda count and not "mean(task type)".

## Conflicting evidence

1. **gte-multilingual-base on MTEB(Multilingual, v2)**: 58.24 (EmbeddingGemma paper
   Table 5, 2025-09-23 snapshot) vs **58.57** `[parquet-recompute]` (131/131, 2026-10-07)
   vs 58.2 (EmbeddingGemma Table 6). Likely task-version/leaderboard drift over
   ~13 months. Carry forward the recomputed 0.5857 with the date, and cite the paper
   value when matching the paper's own comparison table.

2. **Qwen3-Embedding-0.6B MMTEB**: 64.33 (Qwen card, 2025-05-24), 64.34 (Qwen paper +
   EmbeddingGemma paper), 0.6434 `[parquet-recompute]` (2026-10-07). Rounding-level
   conflict only; treat as 64.3.

3. **Leaderboard snapshot dates disagree inside Qwen3 materials**: model card says
   "retrieved ... on May 24th, 2025"; paper Table 2 note says "June 4th, 2025" for the
   same numbers. Neither changes any value; flag when quoting "as of".

4. **MMTEB task count**: 131 (paper prose §2.4, mteb v2.x code) vs 132 (paper Table 1/2).
   Unresolved; current code says 131.

5. **Nomic Embed v2 MIRACL**: card 65.80 (16-language avg) vs paper 66.0 (18-language avg).
   Same model, different language sets — not a real conflict, but a trap if mixed.

6. **BGE-M3 MIRACL: 69.2 (dense, paper) vs `[parquet-recompute]` MIRACLRetrieval 0.7107
   (3 subsets only) vs MIRACLRetrievalHardNegatives.v2 0.6964 (21 subsets)**. The
   parquet values are on the current hard-negatives/downsampled MTEB task, not the
   original MIRACL dev set; the paper's 69.2 is the original benchmark. Do not compare
   across these.

7. **BGE-M3 card reports a corrected MIRACL table (2024-07-01)** stating earlier results
   were lower due to a query-passage dedup bug; the arXiv v5 paper contains the corrected
   numbers. Earlier third-party quotes of BGE-M3 MIRACL may be ~2 pts low.

8. **Arctic-Embed 2.0 paper asserts no English gap**, while its own Table 1 shows
   English-only → multilingual drops of 1.3–3.3 pts for E5/GTE/BGE. Resolution: the gap
   is real for *those* models; Arctic claims only that *its* training recipe avoids it.
   Both statements are correct for their scope.

9. **granite-embedding-311m-multilingual-r2 "65.2 on Multilingual MTEB Retrieval (18
   tasks)"** vs `[parquet-recompute]` MTEB(Multilingual, v2) mean(task) 0.5596
   (131/131). Different subsets entirely (retrieval-only vs all task types); not a
   conflict but not interchangeable either.

10. **KaLM v2.5 scores are not leaderboard-comparable**: the official results dataset
    has only 24/131 MTEB(Multilingual, v2) tasks for it, yet the parquet mean of those
    24 tasks is 0.7596 — higher than Qwen3-8B's full-131 score. That is coverage bias,
    not a real ranking. Same effect for bge-multilingual-gemma2 (28/131 → 0.7750) and
    KaLM v2 (18/131 → 0.7795).

## Gaps

- **No x86 CPU latency published for any model in this angle.** LFM2.5 publishes
  Apple-Silicon llama.cpp latency; granite publishes H100 throughput; EmbeddingGemma
  publishes process memory only. Target hardware (i5-1135G7, no CUDA) → **unverified**.
  This is a real gap for the "local CPU-only" decision.
- **MTEB(Multilingual, v2) mean(TaskType) not recomputed** for most models here (my
  aggregation is mean(task)); only papers' Mean(Type) values are quoted, and only for
  their own snapshot dates.
- **BGE-M3 param count**: HF API exposes no `safetensors` index for `BAAI/bge-m3`;
  568M is taken from third-party tables (Qwen/EmbeddingGemma/Nomic papers list 560–568M).
  The model card itself does not state a parameter count → treat 568M as
  **secondary/approximate**.
- **voyage-4 family and Cohere embed-v4.0**: MTEB(Multilingual, v2) aggregates are
  **unverified** (2/131 tasks in the official results). Voyage's own 2026 blog reports
  RTEB numbers, not MTEB; no MTEB Multilingual aggregate located.
- **google/gemini-embedding-2** (multimodal, released 2026): only 4 tasks in the
  official results → no MMTEB aggregate.
- **EmbeddingGemma-2** (740M, multimodal, 2026-10-06) is outside this text-only angle
  and has no MMTEB numbers found.
- **MTEB(Code, v1) and MTEB(eng, v1)** comparisons for multilingual models were only
  partially recomputed (incomplete task coverage: e.g. bge-m3 22/56 eng v1, 28/41 eng v2)
  — the paper/card published values were used instead where available.
- **Instruction-prompt sensitivity** is not quantified across models here: Qwen3 and
  EmbeddingGemma report 1–5% swings from prompt usage, KaLM/EmbeddingGemma use task
  prefixes, nomic v2 requires `search_query:`/`search_document:`. Leaderboard scores
  assume the officially recommended prompts; a local pipeline that omits them will score
  lower — magnitude per model **unverified** except Qwen3's stated 1–5%.
- **No published MMTEB number for `gte-multilingual-base` in its own card** (card shows
  per-task results and images only, no aggregate table).

# F2 — MTEB results (actual scores: retrieval, classification, clustering, STS)

**Angle 2 — MTEB results.** What the official MTEB leaderboard and first-party model cards /
papers actually report for the major embedding families, with benchmark name, subset, number, and
leaderboard/snapshot date attached to every score.

Every item below carries its source URL. Fetch date is **2026-10-07** unless stated otherwise.
Confidence: `primary` = official leaderboard API / model card / paper / vendor docs;
`primary-dated` = primary but a frozen snapshot of a superseded board;
`secondary` = a vendor blog restating numbers (used only where no primary table exists);
`unverified` = could not be confirmed.

## Angle

The room's retrieval layer needs a *quality* picture, not a *ranking* picture. MTEB's public
numbers are heavily misread in three ways, all of which matter here:

1. **There is no single "MTEB score".** `MTEB(eng, v1)` (56 datasets, scoring bug fixed only in
   v2), `MTEB(eng, v2)` (41 tasks), `MTEB(Multilingual, v1)` (132 tasks) and
   `MTEB(Multilingual, v2)` / MMTEB (131 tasks) are four different suites. A number quoted from one
   is not comparable to a number quoted from another. MTEB's own benchmark metadata says v1 has
   "a known scoring bug" and that v2 "removes common fine-tuning datasets such as MSMARCO for more
   comparable scores" / https://mteb-leaderboard-backend.hf.space/v1/benchmarks/MTEB%28eng%2C%20v1%29 / primary.
2. **Category averages are averages of per-task main metrics, and the main metric differs by
   category.** In `MTEB(eng, v2)`: Retrieval = `ndcg_at_10`, Classification = `accuracy`,
   Clustering = `v_measure`, STS = `cosine_spearman` (per-task metadata, see per-task tables below).
   So "Retrieval 69.44" means "mean nDCG@10 over 10 retrieval datasets", not an accuracy.
3. **Category averages are not all computed over the same task set.** Many models on the live
   board have *partial* coverage; e.g. `BAAI/bge-m3` has a `Summarization` value but **no**
   Classification/Clustering/Retrieval/STS value in `MTEB(eng, v2)` because it is only evaluated on
   27 of the 41 English-v2 tasks. A missing cell is *not* a zero.

Scope note for this repo: all numbers below are **published** benchmarks only. No local evaluation
was run. CPU speed is out of scope here (Angle 5 / F5 owns it).

### How the live board was read

Primary source used throughout: the MTEB leaderboard's own public backend API, which the official
leaderboard front-end calls:
`https://mteb-leaderboard-backend.hf.space/v1/benchmarks/{name}/scores`
(OpenAPI at `https://mteb-leaderboard-backend.hf.space/openapi.json`, `/health` returns
`{"ok": true}`). The Space `mteb/leaderboard` revision at fetch time was
`77f36c15120449b810846e95db1b796c8adfd493`, last modified **2026-10-05T06:59:08Z**
/ https://huggingface.co/api/spaces/mteb/leaderboard / primary. The results dataset behind it,
`mteb/results`, was last modified **2026-10-04T00:24:39Z**
/ https://huggingface.co/api/datasets/mteb/results / primary.

All values below are the raw 0–1 numbers from that API multiplied by 100 to match the displayed
leaderboard scale.

**Caveat on the board's `rank` column** `[INFERENCE]`: the live board's displayed `rank` is *not*
monotone in `Mean(Task)`. Example: `infgrad/Jasper-Token-Compression-600M` is displayed rank 2 with
Mean(Task) 74.75, while `Kingsoft-LLM/QZhou-Embedding` is displayed rank 3 with Mean(Task) 75.97.
Reproducing the first 16 displayed positions exactly required aggregating **per-task ranks**
(average rank across the 41 English-v2 tasks: ingot 12.44, Jasper 15.61, QZhou 19.07, Seed1.5 19.56,
Qwen3-8B 19.68, …), not the Mean(Task) column. Treat the numeric `Mean(Task)` / `Mean(Type)` columns
as the scores and the rank column as an ordinal board position whose exact formula MTEB does not
document on that endpoint. This is flagged as inference, not as a documented fact.

  models that beat it on Classification (`bge-en-icl`, `SFR-Embedding-2_R`, `mongodb/voyage-3-m-exp`)

- **Size vs score is not linear.** Qwen3-0.6B (0.596 B) reaches Retrieval 61.83 / Classification

## Conflicting evidence

1. **Card numbers vs live board for the same suite — real, large, and date-driven.**
   - `NovaSearch/stella_en_1.5B_v5`: 71.19 Avg(56) at rank **3** on the frozen 2024-09-09 v1 board
     (C7f) vs 70.54 Mean(Task) at rank **12** on today's live v1 board (C3). Same suite, same model,
     1.9 points of board movement.
   - `nomic-ai/nomic-embed-text-v1.5`: 62.28 (card, C7g / frozen board C7f) vs 61.09 live v1 (C3).
   - `BAAI/bge-m3`: no MTEB aggregate on its own card (C7b); the *live* board gives it Multilingual-v2
     Retrieval 54.59 with **no** Mean cell (C2), while the Qwen3 card's 2025-05-24 snapshot gives it
     54.60 / 59.56 Mean(Task) / 52.18 Mean(Type) (C7a) and the EmbeddingGemma paper's re-run gives
     59.56 / 52.18 with the same per-type breakdown (C7k). The Retrieval cell agrees across all three
     (54.59 / 54.60 / 54.60); the **Mean(Task) is only available in the two dated sources**, because
     today's board suppresses it for partial-coverage models.
   - `openai/text-embedding-3-large`: 64.6 "MTEB average" (OpenAI announcement, C7j) vs 62.15
     Mean(Type) / 66.43 Mean(Task) on Eng-v2 (C7a) vs no Mean cell at all on the live Eng-v2 board
     (C1). Three different-looking numbers that are three different things.

2. **`rank` is not `Mean(Task)` on the live board** — documented in "How the live board was read"
   above and re-confirmed: Jasper-Token-Compression-600M is rank 2 with Mean(Task) 74.75 while
   QZhou-Embedding is rank 3 with 75.97. Any statement of the form "model X is #N on MTEB" is only
   meaningful with the snapshot date *and* an understanding that the board's ordering is not the
   Mean(Task) column. `[INFERENCE]` on the exact ordering rule (it reproduces a per-task average-rank
   aggregate, not the printed mean).

3. **The board's own model metadata disagrees with the API's summary row.**
   `https://mteb-leaderboard-backend.hf.space/v1/models/Qwen/Qwen3-Embedding-8B` reports
   `zeroShotPct: -1` for that model, while the Eng-v2 summary row reports `zeroShotPct: 95` (and
   Multi-v2 reports 99). The per-benchmark row is the one used above; the model endpoint's −1 is a
   sentinel, not a measurement.

4. **Partial coverage makes "Retrieval average" non-comparable across models.** Live Eng-v2:
   `BAAI/bge-m3` has no Retrieval cell at all (27/41 tasks), `google/gemini-embedding-001` has one
   but `maxTokens` 2048 while Qwen3-8B has 32768, and `mongodb/voyage-3-large` has three task scores
   and no category averages. Comparing a model with 41/41 coverage to one with 27/41 on the same
   column is invalid; the tables above carry the coverage counts so this is checkable.

5. **`mongodb/voyage-3-m-exp` looks like the best model on several subsets and is not on the
   headline board.** It tops 5 of 8 Eng-v2 classification subsets and 3 of 10 retrieval subsets in
   C4b, yet its board rank is 61 and it has 37/41 tasks. MTEB's own blog (primary) explains the
   design intent: the board shows "the top models for their size bracket" and warns "a pre-defined
   leaderboard might only contain 50% of the tasks that you care about"
   / https://docs.mteb.org/blog/mteb-leaderboard-from-a-slow-demo-to-feature-rich-leaderboard/ / primary.

6. **`gemini-embedding-001` has three different "MTEB" numbers in circulation.** 68.16/68.17 by
   dimension in Google's own API docs (unlabelled variant, C7k); 73.30 Mean(Task) Eng-v2 in the Qwen3
   card's 2025-05-24 snapshot and the paper's 2025-06-04 snapshot (C7a); 68.37 Mean(Task)
   Multilingual-v2 both on the live board (C2) and in the EmbeddingGemma paper (C7k). All three are
   primary; none is wrong; none is interchangeable.

7. **`jinaai/jina-embeddings-v3` has no Eng-v2 Classification cell on the live board** (C1) yet its
   paper reports the *highest* English Classification accuracy in its comparison, 82.58 (C7h). The
   paper's 82.58 is a weighted average over its own task selection with the classification adapter;
   the board's Eng-v2 classification set (8 datasets) is a different selection. Not a contradiction —
   a suite mismatch, and a trap when quoting.

8. **Almost no conflict** between the live board and the Qwen3 card / paper for the Qwen3 models
   themselves: 23 of the 24 Qwen3 category cells (Eng-v2 + Multi-v2, three sizes) reproduce exactly.
   The one drift: `Qwen/Qwen3-Embedding-0.6B` Eng-v2 Classification is **85.76** in the card's
   2025-05-24 snapshot and **84.58** on today's board. Likewise `google/embeddinggemma-300m`
   matches its paper exactly (Eng-v2 Mean(Task) 69.67, Multi-v2 61.15 = live board 69.67 / 61.15).
   This is the cleanest available evidence that the *board cells* are stable while *ranks* move.

## Angle

## Claims
- NATS JetStream pull consumer: `MaxAckPending` = consumer-wide cap on delivered-but-unacked messages; stops delivery at limit until acks arrive; documented default 1000; shared across workers of same consumer. / https://docs.nats.io/learn/jetstream/pull-consumers / 2026-11-09 / primary
- NATS JetStream: large pull batch cannot override `MaxAckPending` (e.g. limit 10 + request 100 → pause at 10). Pull batch/outstanding pull requests = request-side bounds; `MaxAckPending` = server-side backpressure. / https://docs.nats.io/learn/jetstream/pull-consumers / 2026-11-09 / primary
- NATS JetStream pull: fetch = batch ≤N or timeout; consume = continuous flow, library keeps pull requests open. / https://docs.nats.io/learn/jetstream/pull-consumers / 2026-11-09 / primary
- NATS JetStream discard (stream storage, not priority): `DiscardOld` evicts oldest to keep latest at limit; `DiscardNew` rejects new publishes at limit. `KEEP_LAST` is not a JetStream discard-policy name. / https://docs.nats.io/learn/jetstream/your-first-stream / search 2026-11-09 / primary (via docs search snippet; do not quote verbatim beyond snippet)
- NATS core queue groups: members sharing name on same subject share load, exactly one member gets each message, server picks random index (uniform-random, not round-robin, can be lopsided short-term). Core is at-most-once; worker death after delivery loses message; durable work queue belongs in JetStream. / https://docs.nats.io/learn/core-nats/queue-groups / 2026-11-09 / primary
- Redis Streams: `XADD key [MAXLEN|MINID [=|~] threshold [LIMIT count]] * field value`; `MAXLEN` evicts oldest (lowest IDs) keeping newest; `=` exact (default), `~` approximate more efficient may leave slightly more than threshold; `LIMIT count` caps evictions examined (default 100× macro-node entries, 0 disables). / https://redis.io/docs/latest/commands/xadd/ / 2026-11-09 / primary
- Redis Streams: XADD O(1) without trim, O(N) with trim (N evicted). / https://redis.io/docs/latest/commands/xadd/ / 2026-11-09 / primary
- Anthropic long-horizon: instruct agent to save progress before context transition, keep durable state outside conversation (structured files: task status, tests, progress note); fresh context reading workspace files can beat compaction alone. Cite "Long-horizon reasoning and state tracking" / prompting best practices page. / https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices / 2026-11-09 / primary
- Anthropic context awareness: some Claude models track remaining context budget; for auto-compacting agents explicitly tell model to save progress and continue, not stop early. / same Anthropic URL / 2026-11-09 / primary
- Anthropic long-context (20k+ tokens): put long data top, query end (up to ~30% quality gain in tests for complex multidocument inputs), structure with XML document/source tags, ground answers in quotes before task. / same Anthropic URL / 2026-11-09 / primary
- Anthropic interruption (server-side tool use): API returns `stop_reason: "pause_turn"`; continue by resending assistant message unchanged. / https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/prompt-templates-and-variables (per search snippet; resolved to platform.claude.com mirror) / 2026-11-09 / primary

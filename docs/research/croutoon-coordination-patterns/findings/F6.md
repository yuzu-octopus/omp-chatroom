## Angle
Digest/compaction strategies: OptMem/OptChat repo, MemGPT/Letta, recursive summarization, LangGraph summarization nodes, Claude Code compaction, context-rot papers on hierarchical summarization vs truncation vs retrieval.

## Claims
- MemGPT proposes "virtual context management" inspired by OS hierarchical memory: data movement between fast/slow memory tiers gives appearance of large memory. Tested on document analysis (far exceed window) and multi-session chat (remember/reflect/evolve). Claim: intelligent tier management + interrupts enables extended context within limited window. Source: https://arxiv.org/abs/2310.08560 | fetch 2026-11-09 | confidence primary (peer-reviewed preprint abstract, arXiv).
- Letta separates three memories: Core Memory (in-context, always visible, editable via memory_insert/replace/rethink), Archival Memory (vector DB, semantic search, NOT auto-populated from overflow, must explicit archival_memory_insert), Conversation History (DB stored, searchable via conversation_search, moves out automatically when full, agent can trigger summarization). Source: https://raw.githubusercontent.com/letta-ai/skills/main/letta/agent-development/references/memory-architecture.md | fetch 2026-11-09 | confidence primary (official skills repo doc).
- Letta compaction code lives in `letta/services/summarizer/` with files `compact.py` (orchestration + build_summarizer_llm_config), `summarizer_sliding_window.py` (sliding-window partial eviction), `self_summarizer.py` (self-compact paths). Release notes 0.16.7 mention overflow-handling fixes + summarizer prompt improvements. Issues #3270/#3279 document sliding-window ignoring percentage (full wipe bug) and GLOBAL_MAX_CONTEXT_WINDOW_LIMIT capping summarizer model. Source: https://github.com/letta-ai/letta/tree/main/letta/services/summarizer ; https://github.com/letta-ai/letta/issues/3270 ; https://github.com/letta-ai/letta/issues/3279 ; https://github.com/letta-ai/letta/releases | fetch 2026-11-09 | confidence primary (first-party repo + issues).
- OptMem (VictorTaelin/OptMem, 2387 stars): append-only log `LOG.txt` (one memory/line, never edited) + rebuildable binary summary tree `TREE/`. Commands: `memo wake` (first cmd/session, bounded print), `memo note "..."` (1 line, max 280 bytes), `memo nap` (answer merges due, synchronous, no background), `memo recall <regex>` (search all), `memo zoom <lo>-<hi>` (open node into two halves), `memo forget <lo>-<hi>` (drop bad summary, rebuilt on next nap). WAKE_LINES is reading budget not storage budget (96 ≈ 8k tokens). Fixed-width records: at 1M memories (608 MB), wake = 0.03s. Subagents must NOT run memo (duplication risk). Source: https://github.com/VictorTaelin/OptMem | fetch 2026-11-09 | confidence primary (author repo README).
- OptChat extends OptMem to full conversation (alpeware/opt-chat): durable append-only JSONL log with fsync; background compactor builds binary summary tree with ≤512 byte nodes (level 0 = 1 msg, level l merges two children); constant view VIEW=128,000 bytes/turn (recent msgs 1 line each, older hierarchical); zoom(id,n) verbatim retrieval in O(log n); incremental folding preserves prompt-cache prefix. Safety: single-writer Unix socket lock (ProcessLock), CoT/thinking never logged, tool outputs capped CAP=30,000 chars, settle-wait blocks turns until view lines summarized. Daemon architecture decouples storage/compactor from Web UI + agy hooks (PreInvocation injects <chat> view, Stop triggers compactor pump). Source: https://github.com/alpeware/opt-chat | fetch 2026-11-09 | confidence primary (impl repo README; note single star, author is implementer not original spec author — original spec gist cited inside).
- LangGraph/LangMem `SummarizationNode` (langmem.short_term): summarizes messages when cumulative tokens reach `max_tokens_before_summary`, replaces with single summary message as [summary_message]+remaining. Params: model, max_tokens (default = trigger), max_summary_tokens default 256 (budget estimate only, not passed to LLM unless model.bind(max_tokens)), token_counter default count_tokens_approximately, three prompts (initial/existing/final). Output writes to `summarized_messages` (decoupled from `messages`), tracks `context["running_summary"]` (RunningSummary with summary text, summarized_message_ids set, last_summarized_message_id) persisted via checkpointer per thread_id. If tokens-to-summarize > max_tokens, only last max_tokens summarized (prevents summarizer overflow). Tool-call atomicity: if last msg in window is AI with tool calls, subsequent tool msgs included. Source: https://langchain-ai.github.io/langmem/reference/short_term/ | fetch 2026-11-09 | confidence primary (official API docs).
- Anthropic threshold compaction (beta `compact_20260112`): API auto-summarizes older context once input tokens hit trigger (default 150,000, min 50,000, only trigger type input_tokens), emits `compaction` block mid-request, subsequent requests drop all blocks prior to compaction block. Managed Agents: always on. Rationale stated: "as a conversation grows, response quality degrades, so compaction replaces older content with a concise summary" + keeps active context small. On-demand compaction variant (beta `compact-2026-09-04`) lets app decide when; options keep-recent-turns (word-for-word tail), background compaction (swap block on arrival), custom summarization prompt. Source: https://platform.claude.com/docs/en/build-with-claude/compaction-threshold.md ; https://platform.claude.com/docs/en/build-with-claude/compaction.md | fetch 2026-11-09 | confidence primary (official API docs).
- Anthropic prompting best practices (Claude Code harness): context window "automatically compacted as it approaches its limit"; advised prompt tells model "do not stop tasks early due to token budget... save progress/state to memory before context refreshes." Counter-advice: "consider starting with a brand new context window rather than using compaction... latest models are extremely effective at discovering state from local filesystem" (prescriptive restart: pwd, review progress.txt/tests.json/git logs). Also: write tests in structured format (tests.json) before work, setup scripts (init.sh), git as state tracking. Claude Code memory docs: each session fresh window; CLAUDE.md (target <200 lines, longer reduces adherence) + auto memory (first 200 lines / 25KB at load). Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices.md:808-860 ; https://code.claude.com/docs/en/memory.md | fetch 2026-11-09 | confidence primary (official docs).
- RAPTOR (Sarthi et al., 2024): recursively embed/cluster/summarize chunks bottom-up into tree with differing abstraction levels; at inference retrieve across levels. On QA requiring multi-step reasoning, coupling RAPTOR retrieval with GPT-4 improves QuALITY best performance by 20% absolute accuracy. Counterpoint to flat chunk retrieval: hierarchical summaries enable holistic doc context. Source: https://arxiv.org/abs/2401.18059 | fetch 2026-11-09 | confidence primary (paper abstract).
- Hierarchical merging error amplification (Ou & Lapata, 2025): recursive merging of intermediate summaries "can amplify LLM hallucinations, increasing risk of factual inaccuracies" for >100K token docs. Mitigation: contextual augmentation — replace intermediate summaries with relevant source context, refine with context as evidence, or align via citations. Result: augmentation consistently outperforms zero-shot + plain hierarchical merging on Llama 3.1 (legal + narrative domains); refinement pairs best with extractive summarization. Source: https://arxiv.org/abs/2502.00977 | fetch 2026-11-09 | confidence primary (paper abstract).
- Context rot in retrieval is attention competition, not length (Liu, 2026-11-03): neutral filler to 32K tokens costs nothing (accuracy 0.97–1.00 on Qwen2.5-1.5B); evidence-format statements at same positions drop to 0.16–0.33; single rival-value statement multiplies loss 9–110x, each additional rival adds. Attention mass on evidence explains up to 58% of variance across 126,473 trials; log length ≤8%. Masked-filler protocol claiming length hurts reproduces on MMLU (11–18 pts lost at 30K) but fails visible control in retrieval (masking costs 45 pts, same filler visible costs none). Source: https://arxiv.org/abs/2611.04169 | fetch 2026-11-09 | confidence primary (paper abstract; very recent, single author).
- Context rot in long-horizon search (Xia et al., 2026-06-29): models "give up or provide uncertain incorrect answers long before exhausting context window" — inconclusive search failures, common even on easy/moderate queries. Study 4 flagship models × 3 benchmarks (BrowseComp, BrowseComp-Plus, xbench-DeepSearch), 7 context-management methods (compaction / trimming / isolation). All methods redirect from give-up toward exploration by decreasing peak context length; context management = test-time scaling. Method selection is model-dependent (isolation suits stronger agentic model; recent-context + summaries better cost/accuracy for weaker). Parallel sampling behavior-aware filter (drop give-up/uncertain trajectories) gains 2.6–4.9%. Source: https://arxiv.org/abs/2606.29718 | fetch 2026-11-09 | confidence primary (paper abstract).
- "Lost in the Middle" (Liu et al., 2023): position of relevant info matters — performance highest at beginning/end, degrades in middle of long contexts "even for explicitly long-context models." Distinct from literal truncation: information present but unusable. Source: https://arxiv.org/abs/2307.03172 | fetch 2026-11-09 | confidence primary (paper abstract).
- Truncation vs summarization head-to-head is narrow: BERT study (2024) on Indonesian news-topic classification — first-70-tokens truncation macro-F1 0.7780 vs extractive summarization 0.7773 vs full-text 0.7863; authors note news lead-bias likely explains it. Not generalizable to LLM long-context. Source: https://arxiv.org/abs/2403.12799 | fetch 2026-11-09 | confidence primary (paper, but narrow scope — do not over-claim).
- No arXiv paper exists for OptMem/OptChat specifically; evidence is repo README only (VictorTaelin/OptMem, alpeware/opt-chat implementations). No OptMem/OptChat peer-reviewed paper found. Source: web search 2026-11-09 | confidence secondary (search absence, not primary proof).

## Conflicting evidence
- Anthropic sources conflict internally: compaction docs recommend server-side summarization to sustain long chats, but prompting best practices say fresh-context restart (filesystem rediscovery) can beat compaction for code tasks. Difference is domain: chat/task-oriented tool-use vs filesystem-grounded coding. Carry forward as conditional, not contradiction.
- RAPTOR (+20% QuALITY via tree retrieval) vs hierarchical merging hallucination amplification (Ou & Lapata): tree methods help QA retrieval but recursive summary merging risks factual drift. Reconcile: retrieval-time tree (RAPTOR) vs generation-time merge (hierarchical summarization) are different uses; augmentation/citation alignment mitigates merge drift.
- Context-rot papers disagree on mechanism: Liu 2026 says length cheap, competition costly (attention dilution by rivals); Xia 2026 says accumulation of failed/repetitive exploration causes premature give-up. Both agree peak-context reduction helps but for different reasons. Reconcile: short-context retrieval = competition; long-horizon agent = accumulation fatigue. omp-chatroom room logs hit both.

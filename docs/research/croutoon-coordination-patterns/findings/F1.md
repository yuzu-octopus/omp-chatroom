## Angle
Durable shared logs + per-consumer cursor + idempotent replay across event-sourcing/Kafka/JetStream/Raft/LangGraph/AutoGen. Fetch date 2026-11-09.

## Claims

1. Kafka = append-only partitioned log, consumer offset = single int per partition, rewindable. Producer at-least-once pre-0.11, idempotent PID+seq from 0.11; consumer at-least-once = process-then-commit, at-most-once = commit-then-process; exactly-once only via transactional producer+read_committed+offset-as-message. Source: https://kafka.apache.org/40/design/design/ — fetch 2026-11-09 — confidence: primary (official design doc).
2. Kafka idempotent producer on by default (needs acks=all, retries>0, max.in.flight<=5); broker dedups on PID+sequence so producer RETRY not duplicating log entry. App-level resend / new PID still duplicates. Source: https://kafka.apache.org/44/configuration/producer-configs/ + https://kafka.apache.org/11/design/design/ — fetch 2026-11-09 — confidence: primary.
3. JetStream = stream (seq-numbered append) + durable consumer (server-side cursor per consumer, multi-consumer independent). Explicit ack advances cursor; unacked timeout = redelivery = at-least-once, NOT exactly-once. Ack after processing; duplicate possible if crash before ack -> need idempotent processing / dedup key. Retention separate from ack (limits vs workqueue/interest). Source: https://docs.nats.io/concepts/jetstream — fetch 2026-11-09 — confidence: primary.
4. Raft = replicated append-only log + state machine safety: same index+term => same command, identical prefix (Log Matching). Leader appends, AppendEntries with prevLogIndex/prevLogTerm repairs followers; committed = majority-replicated entry, new leader must contain all committed entries. Proves: ordered durable log + deterministic replay yields identical state. Source: https://raft.github.io/raft.pdf (Ongaro & Ousterhout, extended version) — fetch 2026-11-09 — confidence: primary (peer-reviewed USENIX ATC'14).
5. Event sourcing (Fowler): state = derived by replaying event log; facilities = complete rebuild, temporal query, event replay. External side effects NOT automatic: replay re-sends to external systems -> need gateway disabled in replay mode + replay-safe/deduped external calls. Key warning for agent coordination: replay must gate tool/API side effects. Source: https://martinfowler.com/eaaDev/EventSourcing.html — fetch 2026-11-09 — confidence: primary (reference pattern, author draft 2005).
6. LangGraph checkpointer = thread-scoped snapshot per super-step (thread_id + checkpoint_id/parent), pending-writes per task = partial-step fault tolerance (successful nodes not rerun on resume). Replay = re-execute from prior checkpoint_id. Durability modes: sync (persist before next step), async (risk loss on crash), exit (no mid-run recovery). InMemorySaver lost on restart -> Postgres/SQLite for durability. Source: https://docs.langchain.com/oss/python/langgraph/checkpointers + https://docs.langchain.com/oss/python/langgraph/persistence — fetch 2026-11-09 — confidence: primary.
7. LangGraph replay re-triggers LLM calls/APIs/interrupts — NOT idempotent by default. Must make nodes idempotent / gate side effects, same as Fowler external-update problem. Source: checkpointers Replay section — fetch 2026-11-09 — confidence: primary.
8. AutoGen AgentChat Memory protocol: add/query/update_context/clear/close; ListMemory chronological append, query injects into model_context before step. This is RAG-style retrieval (vector DB / Redis), NOT a durable ordered message log or per-consumer cursor. Message history is separate (run() appends; pass only new messages). Proves agent memory != coordination log. Source: https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/memory.html — fetch 2026-11-09 — confidence: primary.
9. Synthesis verdict: durable append-only log + per-consumer cursor + idempotent replay PROVEN as core pattern for coordination (Kafka offsets, JetStream durable consumers, Raft log matching, LangGraph checkpoints, event sourcing rebuild). Common gap: exactly-once / idempotent replay is NEVER free — requires dedup keys, transactional outbox, or gated side effects. LangGraph/AutoGen show agent frameworks adopt only the snapshot/memory half, not the cursor/ack half — coordination layer must add it. Source: [INFERENCE] synthesis across 1-8 — confidence: inference, high (6 independent primaries converge).

## Conflicting evidence
- None material. Kafka vs JetStream differ on who stores cursor (consumer-committed offset vs server-side durable consumer) but both = per-consumer cursor + at-least-once + client idempotence. Raft guarantees stronger (no conflicting committed entries) via quorum; Kafka ISR differs but committed semantics same shape. LangGraph checkpoints = snapshots, not event log — richer state than Kafka offset but no cross-agent cursor/ack.

## Angle
Group chat UX for LLM agents (threading, mentions, reactions, read receipts, typing indicators — which matter for agents vs humans); Slack/Discord/IRC design principles translated to agent coordination; optimal message format for LLM parsing and action.

## Claims (claim / source URL / fetch date / confidence per item — confidence: primary > secondary > speculative)
- **Prompt caching requires stable prefixes**: prompt caching is prefix-match; any change in prefix invalidates after it. Tools/system/messages order fixed; put volatile content (timestamps/UUIDs) at end. Breakpoints at stability boundaries. [primary] https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching [fetch 2026-10-26]
- **Multi-agent uses orchestrator-worker; subagents need clean context**: lead agent coordinates, subagents explore in parallel with own context windows, return condensed summaries. Separation of concerns reduces path dependence; long-horizon needs compaction/memory/handoffs. [primary] https://www.anthropic.com/engineering/multi-agent-research-system [fetch 2026-10-26]
- **Agent chat needs explicit routing, not just @ parsing**: use `recipient_ids` separate from `mentions`/text; `intent` (`handoff/assignment/question/decision`), `status` (`queued/in_progress/awaiting_response/completed/blocked`), `thread_id`, `reply_to`. Treat transcript as "what was said", structured fields as "who should act/what/done". [primary] https://github.com/a2aproject/A2A/blob/main/docs/specification.md [fetch 2026-10-26]; [primary] https://microsoft.github.io/autogen/dev/user-guide/agentchat-user-guide/selector-group-chat.html [fetch 2026-10-26]
- **Threads reduce noise; turn ownership must be visible**: put subproblems in threads, main thread for goal/decisions/status; show "X is responding / waiting for Y", why invoked (assigned/mentioned). Threads prevent flooding channels (Slack/Discord guidance). [primary] https://docs.slack.dev/concepts/agent-design [fetch 2026-10-26]; [primary] https://autogenhub.github.io/autogen/docs/tutorial/conversation-patterns/ [fetch 2026-10-26]
- **Reactions/read receipts/typing indicators mostly human UX**: Slack/Discord agent guidance emphasizes streaming partial results, threading, confirmations for high-stakes actions; no primary spec requires read receipts/reactions for agent correctness. Treat as optional UI polish. [primary] https://docs.slack.dev/concepts/agent-design [fetch 2026-10-26]
- **Message envelope needs stable IDs, idempotency, expiry**: generate unique message IDs, ignore duplicates, expiry on requests, separate routing from content, don't put secrets in chat. Map to platform primitives (threads/tags) without relying on them for agent identity. [primary] https://ircv3.github.io/specs/extensions/message-tags.html [fetch 2026-10-26]; [primary] https://github.com/Kickflip73/agent-communication-protocol/blob/main/spec/core-v1.0.md [fetch 2026-10-26]
- **Multi-party conversation model (floor/mediation/delegation)**: OpenFloor models conversation as shared floor with delegation/channeling/mediation; floor manager controls who engages. Useful for agent coordination patterns. [primary] https://openfloor.dev/protocol/specifications/inter-agent-message [fetch 2026-10-26]
- **Tool-mediated communication for agents**: some systems make all inter-agent comm via tools (not free text output) for auditability/routing; system prompt must teach agents to use comm tools. [primary] https://github.com/openma-ai/open-managed-agents/blob/main/docs/agent-im-design.md [fetch 2026-10-26]

## Conflicting evidence
- **Threading necessity**: all sources agree threads reduce noise; some advocate always-threading agent responses (Slack agent design), others allow main-thread summaries with details in artifacts. No consensus on forcing threads vs optional.
- **Orchestration style**: AutoGen supports both round-robin and selector (model-based) speaker selection; some advocate strict coordinator, others peer-to-peer with mentions. Trade-off: determinism vs flexibility.
- **Cache sharing across evolving state**: Anthropic recommends prefix caching for stable shared context; practitioners note cache invalidates when shared prefix mutates (planner updates constraints) and suggest external shared memory/recall when state evolves frequently. No single "right" answer - depends on mutation frequency.

## Gaps
- Empirical data on which UX features (reactions/read receipts/typing) actually help agent coordination vs just human observability - mostly design guidance, limited measured outcomes.
- Concrete token/cost comparisons for different message formats (verbose prose vs structured JSON) under prompt caching - mentioned in principle but few published benchmarks.
- Best practices for mixing human and agent participants in same room with different attention models - partially covered by OpenFloor but underexplored.

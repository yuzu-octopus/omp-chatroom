# F2: Context window management in multi-agent systems

## Angle

How Claude Code, Cursor, Devin (Cognition), and Anthropic's multi-agent research system manage/swarm context: orchestrator/worker splits, subagent context isolation, summarisation/compaction, noise filtering, staleness and cache hits. What is the right amount of shared context per agent? How do they avoid pollution? Compaction vs retrieval vs distill. (Resolves the F1/F5 gap: how much context agents should actually share per turn.)

## Claims

### 1. Subagents run in their own isolated context window everywhere (orchestrator/worker split)

- **Claim:** In Claude Code, each subagent runs in its own context window with its own system prompt, tool access, and permissions; its tool calls stay out of the parent's context and only a summary returns ("Use one when a side task would flood your main conversation... the subagent does that work in its own context and returns only the summary"). | **Source URL:** https://code.claude.com/docs/en/sub-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Subagents preserve context (exploration/implementation out of the main conversation), enforce constraints (limit tools), specialize behaviour (focused system prompts), and control cost (route to cheaper models like Haiku); built-in Explore/Plan agents start without CLAUDE.md and git snapshot to keep research fast/cheap. | **Source URL:** https://code.claude.com/docs/en/sub-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Subagent `description` fields all load into the main context, so they must be kept short; combined non-built-in descriptions over ~15,000 tokens trigger a startup warning — descriptions are themselves shared-context cost. | **Source URL:** https://code.claude.com/docs/en/sub-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** In Cursor, each subagent operates in its own context window, starts with a clean context (parent includes relevant info in the prompt; no prior conversation history), works autonomously, and returns a final message; built-in Explore (codebase search) and Browser (noisy DOM/screenshot filtering) exist specifically because those tasks generate intermediate output that would bloat the main context. | **Source URL:** https://cursor.com/docs/subagents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cursor built-in Explore uses a faster model to run ~10 parallel searches in the time one main-agent search takes; context isolation + model routing + specialized prompts are the three stated reasons these are subagents. | **Source URL:** https://cursor.com/docs/subagents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Anthropic's Research system uses orchestrator/worker: a lead agent plans and spawns parallel subagents with their own context windows that explore independently (web search, interleaved thinking) and return findings; a separate CitationAgent then grounds claims. Each subagent = separation of concerns (distinct tools, prompts, exploration trajectories), reducing path dependency. | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Devin (Cognition) runs a manager-Devin/child-Devin pattern for large scope (features spanning PRs, multi-service migrations): manager splits work, children execute, manager synthesizes; agents do NOT automatically share state — "context has to be communicated deliberately", and models by default assume shared state with children that does not exist (required dedicated fixing). | **Source URL:** https://cognition.com/blog/multi-agents-working | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

### 2. The right amount of shared context: task brief in, distilled summary out (1–2k tokens)

- **Claim:** Anthropic's rule: subagents "may explore extensively, using tens of thousands of tokens or more, but return only a condensed, distilled summary of their work (often 1,000–2,000 tokens)". Independent corroboration (Cerebras, Apr 2026): line cooks get "the minimum viable context to cook one specific dish" and "return a summary of their work back to the Head Chef"; the orchestrator is stripped of all tools other than `delegate_task` so worker exploration never enters its context. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://www.cerebras.ai/blog/lessons-learned-from-building-multi-agent-workflows | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Anthropic's delegation recipe: the lead agent's task brief must contain objective + output format + tool/source guidance + clear task boundaries; vague briefs ("research the semiconductor shortage") cause duplicated work and gaps (observed: 3 agents covering the same 2025 supply chain while 2021 crisis unexplored). | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Anthropic's effort-scaling rules: simple fact-finding = 1 agent with 3–10 tool calls; direct comparison = 2–4 subagents with 10–15 calls each; complex research = 10+ subagents with divided responsibilities — explicit budgets prevent overinvestment (a common early failure: 50 subagents for simple queries). | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cognition's divide-by-context principle: "give each subagent a piece of work that needs little from the rest of the system and have it hand back a compact result" (good: independent research paths, clean-interface components, black-box verification); splitting by problem type creates a lossy "telephone game" where each handoff degrades fidelity. | **Source URL:** https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cognition's smart-friend 80/20: sharing a fork of the primary's full context with the consulting model plus asking broad questions ("what should I do?") and letting the smart model decide what is interesting beats carefully-curated subsets; the reverse channel matters too — the consultant should redirect ("investigate important_file.py and ask again") and volunteer unasked trajectory-level guidance. | **Source URL:** https://cognition.com/blog/multi-agents-working | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

### 3. Anti-pollution: fresh contexts beat big contexts (context rot)

- **Claim:** Context rot (Chroma, 18 LLMs incl. GPT-4.1, Claude 4, Gemini 2.5, Qwen3): performance degrades with input length even on fixed-complexity synthetic tasks; degradation steepens for low needle-question similarity pairs and with topically-related distractors (non-uniform per distractor, amplified at length); NIAH lexical retrieval overstates long-context robustness. | **Source URL:** https://www.trychroma.com/research/context-rot | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Anthropic treats context as finite with diminishing marginal returns ("attention budget"): every token depletes it; n² pairwise attention stretches thin, training distributions skew short, position interpolation degrades position sense — a performance gradient, not a hard cliff. Guiding rule: smallest possible set of high-signal tokens. Independent outcome corroboration (Cognition): clean-context reviewers with NO shared context catch ~2 bugs/PR (~58% severe) on Devin-written PRs specifically because the short context "makes the agent smarter because of the math of attention" — see the following claim. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://cognition.com/blog/multi-agents-working | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cognition's clean-context reviewer: a review agent with NO shared context (only the diff, re-discovering context from scratch) catches ~2 bugs/PR (~58% severe) on Devin-written PRs, looping to find new bugs each cycle — the short context "makes the agent smarter because of the math of attention"; the communication bridge back (coding agent filtering review findings against user intent/scope) is what prevents looping/out-of-scope work. | **Source URL:** https://cognition.com/blog/multi-agents-working | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cursor's anti-bloat rules: @-mention only files you know are relevant (else let Agent search); rules short/scoped/under 500 lines, point at canonical examples instead of copying them; never attach whole folders, large logs, long references; start a new chat on task switch (`/clear` equivalent); check the per-category context breakdown ring when large. | **Source URL:** https://cursor.com/docs/agent/prompting ; https://cursor.com/docs/rules | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Claude Code's anti-bloat rules: `PUT /clear` when switching tasks ("old conversation crowds out the files you need next and costs tokens on every message"); delegate large reads to subagents; `/context` live breakdown; MCP tool definitions deferred and loaded on demand via tool search; skills load on demand (descriptions only at start). | **Source URL:** https://code.claude.com/docs/en/context-window.md ; https://code.claude.com/docs/en/how-claude-code-works.md | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

### 4. Compaction (summarise-and-restart)

- **Claim:** Claude Code compacts automatically approaching the limit (same as `/compact`); the summary is produced by passing message history to the model, preserving architectural decisions, unresolved bugs, implementation details while discarding redundant tool outputs; re-injects from disk after compaction: system prompt, output style, project-root CLAUDE.md + unscoped rules, auto memory, skill descriptions, git snapshot (fresh), plan-mode plan, up to 5 recently-read files (>5k-token files become path references), invoked skill bodies (5k tokens/skill, 25k total, oldest dropped); path-scoped rules and nested CLAUDE.md reload on demand; hook-added context is summarized away unless SessionStart-on-compact re-injects it. | **Source URL:** https://code.claude.com/docs/en/context-window.md ; https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Compaction controls: `/compact [focus instructions]` to steer the summary; `/rewind` + Summarize-from/up-to-here for partial compaction; `/autocompact <tokens>` to set the trigger threshold; `DISABLE_AUTO_COMPACT` / `DISABLE_COMPACT` envs; auto-compact stops with an error (instead of looping) after a few attempts if one giant file/output refills context immediately. | **Source URL:** https://code.claude.com/docs/en/context-window.md | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Compaction tuning advice: maximize recall first (capture everything), then iterate to precision (remove superfluous content); cheapest safe form is tool-result clearing (drop raw tool outputs from deep history); available as a platform feature on the Claude Developer Platform. Shipped corroboration: tool result clearing is now a server-side context-editing strategy (`clear_tool_uses_20250919`) — clears oldest tool results in chronological order past a threshold, replacing each with placeholder text; intended for agentic workflows where old outputs (file contents, search results) are no longer needed once processed. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://platform.claude.com/docs/en/build-with-claude/context-editing | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cursor compresses older conversation into a summary as the fixed window fills; the context ring breaks usage into system prompt / tools / rules / skills / MCP / subagents / summarized conversation / conversation. | **Source URL:** https://cursor.com/docs/agent/prompting | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Anthropic research system: lead agent writes its plan to Memory because "if the context window exceeds 200,000 tokens it will be truncated"; agents spawn fresh subagents with clean contexts on approach to limits and pull the saved plan back from memory (handoff continuity). | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

### 5. Retrieval (just-in-time) vs distill (note-taking / artifacts) vs compact

- **Claim:** Anthropic's hybrid: cheap/always-relevant context loads up front (CLAUDE.md), everything else just-in-time via tools (glob/grep, targeted queries, head/tail over big data instead of loading whole objects); agents keep lightweight identifiers (paths, queries, links) and progressively disclose — metadata (hierarchy, names, timestamps) guides retrieval; "do the simplest thing that works". Same-vendor corroboration for the JIT half: the fold-subagents article prescribes single-loop-with-progressive-disclosure (skills + tool search loading on demand) as frequently beating orchestrator-subagent designs — see the counter-direction claim below. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Structured note-taking (agentic memory): agent writes NOTES.md / to-do state / file-based memory-tool entries outside the window, re-pulled later; persistent across resets with minimal overhead (ex: Claude-playing-Pokémon multi-hour tallies/maps/strategies surviving context resets). | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Filesystem-artifact pattern (anti-telephone-game): subagents write structured outputs (code, reports, visualisations) to external systems and pass lightweight references back instead of routing everything through the coordinator — prevents multi-stage information loss and token overhead. | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Cognition: writes stay single-threaded, agents contribute intelligence — the shape that works is map-reduce-and-manage (manager splits, children execute, manager synthesizes), not unstructured swarms of negotiating agents; Devin also calls read-only DeepWiki subagents for codebase context (subagent-as-tool-call). | **Source URL:** https://cognition.com/blog/multi-agents-working | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** When to choose which (Anthropic): compaction = conversational flow with heavy back-and-forth; note-taking = iterative development with clear milestones; multi-agent = parallel research/analysis. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Counter-direction (Oct 2026, fold-subagents): with Opus 4.5+ class models, a single agent loop with progressive disclosure (skills + tool search loading on demand) frequently beats orchestrator-subagent designs on quality at lower cost/latency; keep subagents only when (a) measurable degradation from context bloat, (b) parallel fresh-context work discardable after, or (c) tool-selection/instruction conflicts force separation. System-prompt hygiene matters: Claude Code's own prompt cut >80% via progressive disclosure. | **Source URL:** https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

### 6. Staleness, cache hits, and coordination costs

- **Claim:** F1's cache-stability rule governs shared context: byte-identical prefixes hit cache; volatile/live state must ride in the tail (user message / runtime_state), never in the system prompt ahead of history/tools — directly constrains how per-turn swarm digests should be injected. | **Source URL:** https://platform.claude.com/docs/en/build-with-claude/prompt-caching (via F1.md) | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Claim:** Artifact/reference-passing doubles as cache hygiene: stable identifiers in the prefix stay cache-hot while bulky volatile payloads live outside the window, fetched on demand. | **Source URL:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary, inference flagged: synthesis of two primaries]
- **Claim:** Synchronous orchestrator-worker execution is a known bottleneck: lead waits for each subagent batch, cannot steer mid-flight, subagents cannot coordinate, one slow subagent blocks all — async execution is the expected direction with open problems in result coordination, state consistency, error propagation. | **Source URL:** https://www.anthropic.com/engineering/multi-agent-research-system | **Fetch date:** 2026-10-26 | **Confidence:** [primary]

## Conflicting evidence

- **Share-everything vs share-minimal:** Cognition's older principle was "share as much context as possible between agents (same sources, todo list, plan files, priors)"; its newer finding is that zero-shared-context reviewers outperform (clean context = smarter). Resolution in the sources: share *task framing* (objective/format/boundaries/plans) broadly, share *working trace* minimally — coordination state yes, exploration exhaust no. | **Sources:** https://cognition.com/blog/multi-agents-working (both the old-principles recap and the new experiments) | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Subagents vs single loop:** Anthropic's research system and context-engineering posts prescribe subagent architectures as a core long-horizon technique, while Anthropic's Oct-2026 fold-subagents article shows single-loop-with-skills beating orchestrator-subagent on enterprise deployments. Resolution in the sources: subagents win for parallel breadth-first work with discardable contexts; single loop wins for tightly-coupled chains sharing evolving state (the telephone-game loss dominates). Model capability shifts the boundary (Opus 4.5+ manages more per loop). | **Sources:** https://www.anthropic.com/engineering/multi-agent-research-system ; https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop | **Fetch date:** 2026-10-26 | **Confidence:** [primary]
- **Fork-full-context vs distill:** Cognition's smart-friend 80/20 says fork the primary's full context to the consultant; Anthropic's research-system says return 1–2k-token distillations. Not contradictory on inspection: full-context fork is for *consultation on the same live problem* (peer advisory), distillation is for *fan-out results* returned to a synthesizer. Direction of information flow differs. | **Sources:** https://cognition.com/blog/multi-agents-working ; https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents | **Fetch date:** 2026-10-26 | **Confidence:** [primary, inference flagged]

## Gaps

- **Devin internals:** no published token limits, compaction/retrieval pipeline details, or per-agent context budgets from Cognition; Devin picture reconstructed from blog-level descriptions (manager/child, DeepWiki subagents, Memory+Dreaming), not docs or source.
- **Cursor internals:** subagent context budgets, summarisation algorithm/trigger thresholds, and resume-agent retention semantics not specified in public docs beyond "compresses older parts into a summary".
- **Quantitative per-turn shared-context sizing:** the 1–2k-token distillation figure is Anthropic's observed norm, not a controlled optimum; no primary-source A/B data on digest size vs downstream task quality for chat-style (non-research) swarms.
- **Staleness/versioning:** no primary-source protocol found for versioning shared context across agents (who invalidates, vector clocks vs last-write-wins); artifact-reference pattern implies it but no spec.
- **Compaction evals:** recall-vs-precision tuning guidance is qualitative ("start with recall, iterate to precision"); no published compaction-fidelity benchmarks from any of the four vendors.

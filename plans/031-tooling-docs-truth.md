## Why this matters

Lint resolves Biome from the network on every run (no devDependency, lockfile entry, or vendored binary — an observed 22 downloads), so offline lint fails and CI can drift between runs. AGENTS documents `bun check` and the two split-suite halves but no script exists for either, so newcomers copy-paste nine filenames. The manifest advertises `omp.features` flags nothing reads, so disabling a feature is silently ignored. HANDOFF still reports 550 pass/551 run at host 18.12.2 while the gates are 604/605 at 18.18.1 — the exact stale-count class plan 011 fixed once, regressed. The discovery probe runs its parser via `python3`, violating the repo's own `uv`-only hygiene.

## Steps

### Step 1: Pin Biome and verify offline lint

Add the exact `@biomejs/biome` version `bunx` currently resolves to `devDependencies`, run `bun ci` (or the repo's lockfile refresh) to update `bun.lock`, and verify `bun run lint` passes. Verify the pin by checking `bun.lock` contains the entry.

**Verify**: `cd plugin && bun run lint` → exit 0; `grep -n "biome" bun.lock` → entry present.

### Step 2: Script the documented gates

Add `check` (`bun check` — wait, `bun check` IS the native command; the script must not shadow it — name it `check:types` or document why a script can't be named `check`. Read the AGENTS.md note and the Bun docs behavior first; if shadowing is a problem, add `typecheck:fast` + `test:halves-a`/`test:halves-b` mirroring the exact AGENTS.md halves). Keep CI calling what it calls today.

**Verify**: `cd plugin && bun run test:halves-a && bun run test:halves-b` (or the chosen names) → both green; CI file untouched.

### Step 3: Honor the features flags (or remove them)

Gate the three `register*` groups in `index.ts` on their `omp.features` flags with default-true preserved (read the flag the way the host exposes manifest features to extension code — check the host API first; if the host does NOT expose feature flags to code, DELETE the `features` block from the manifest instead and say so). Either outcome makes the manifest honest.

**Verify**: `cd plugin && bun test tests/drift.test.ts tests/host-contract.test.ts` → pass; default load path unchanged (all features load).

### Step 4: Refresh HANDOFF counts and live-host delta

Update `HANDOFF.md`'s suite table to the current gates (read the real numbers from a green run — do NOT copy 604/605 blindly; run the suite halves and record what passes) and add a short paragraph stating what was verified live on 18.18.1 vs carried over from the 18.12.3 live evidence. This is the user-visible truth record — numbers must be measured, not transcribed.

**Verify**: numbers in HANDOFF match a run you performed; `git diff` on HANDOFF shows only the table + paragraph.

### Step 5: Run the probe parser via uv

Change `discovery-probe.sh` to invoke the parser with `uv run python` (matching repo hygiene), keeping heredoc, exit codes, and scoring byte-identical. If `uv` is unavailable in the executor env, use the repo's documented Python path and note it — do not break the probe.

**Verify**: `bash -n plugin/scripts/discovery-probe.sh` → syntax OK; parser produces identical output on a fixture input (if the probe has a self-test or sample, run it).

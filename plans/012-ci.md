## Why this matters

There is no CI: no `.github/` directory exists at the repo root. The full
gate (tsc + biome + 213 tests) only runs when a human remembers to run it,
which is exactly how the suite-size docs drifted and how a future host bump
silently breaks the deep-subpath imports. The repo already has everything CI
needs — `bun test tests/`, `bunx --bun tsc --noEmit`, `bunx --bun biome
check`, all pinned in `package.json` scripts — so this plan is one workflow
file that runs the existing gate on push and PR.

## Steps

### Step 1: Write the workflow

Create `.github/workflows/ci.yml`:

```yaml
name: ci
on:
  push:
  pull_request:
jobs:
  gate:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: plugin
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: "1.4.2"
      - run: bun install --frozen-lockfile
      - run: bun run typecheck
      - run: bun run lint
      - run: bun test tests/
```

Notes for the executor:

- `--frozen-lockfile` fails if `bun.lock` drifts from `package.json` — that
  is load-bearing (plan 010's whole point is the lock means something).
- Keep `bun test tests/` (not `bun run test`) — identical today, but the
  explicit path survives a future script rename; either is acceptable, pick
  one and be consistent.
- No `timeout-minutes` below 10 — the suite can take ~40 s plus install.
- If `oven-sh/setup-bun@v2` doesn't accept `1.4.2` (check the action inputs),
  use the closest documented input and record the choice in the commit message.

**Verify**: the YAML parses (see Commands table) and every `run:` line
matches a `plugin/package.json` script or an equivalent explicit command.

### Step 2: Prove HEAD would pass CI

From `plugin/`, run the exact CI sequence locally:

```sh
bun install --frozen-lockfile && bun run typecheck && bun run lint && timeout 500 bun test tests/
```

**Verify**: exit 0 end to end. If `--frozen-lockfile` fails on a clean HEAD,
STOP and report (the lock already drifts — plan 010 must land first).
